## Why finite precision determines the exact Smith data

Every pivot has its exact valuation below the working precision. At a new valuation level, the verifier checks divisibility of the entire active block by the proposed pivot power. Subsequent row subtraction and unit rescaling preserve this divisibility, so repeating the global test at every same-valuation pivot is unnecessary. Dividing the pivot's unit part is legal in the local ring. All target pivot-column entries are checked divisible by the pivot power, and elimination is checked exact.

After the pivot column has been cleared, elementary column operations can remove the pivot row's remaining entries without changing the active block. Therefore deleting the pivot row and column faithfully records a local Smith step. The final active block is zero at the working precision.

A zero residual block modulo a fixed prime power alone would **not** exclude hidden higher-valuation invariants. Here that gap is closed independently: integer Jacobi supplies inner derivations, and the rank-30 inner matrix modulo 1009 gives 30 rationally independent inner derivations. Rational change of basis and scaling identify the rational kernels of the ambient and scaled derivation matrices. Consequently the scaled matrix has rational rank at most 961−30=931. Its 931 verified nonzero local pivots give the reverse bound. No further nonzero invariant is possible. The third implementation's precision-five result already suffices because the largest reported valuation is four.

The manuscript formula for the derivation matrix agrees with all implementations: the row corresponding to (i,j,k) represents the kth coordinate of D[ei,ej]−[Dei,ej]−[ei,Dej]. The matrix columns use (output,input) order, consistently in the Python, C++, and manuscript definitions.

## Integer-width audit

The scaled coefficients exceed the exact-integer range of IEEE double precision. The export script explicitly converts base coefficients to Python integers before multiplying by prime powers. The portable JSON was parsed using exact Python integers in this audit. No floating-point mathematical computation is used.

For the ambient and adapted Jacobi checks, the crude bound 3·31·518400² = 24,992,686,080,000 on the absolute sum of products fits comfortably in signed 64-bit arithmetic; the C++ implementation additionally accumulates Jacobi products in signed 128-bit integers. Modular field products involve residues at most 1008, so its signed-int arithmetic is safe. Bracket-generation arithmetic uses 64-bit intermediates where needed. The Python fixed-width bracket sums of field-residue vectors also fit in signed 64 bits under the conservative bound 31²·1008²·518400.

The C++ local modulus is 1009⁶ = 1,055,229,678,769,825,441, below 2⁶⁰. Residue multiplication uses unsigned 128-bit arithmetic; products lie below 2¹²⁰. Exact extended-Euclidean intermediates and coefficient scaling fit signed 128 bits. Sanitizer execution supplies an additional dynamic check for the actual complete run. The independent precision-five implementation uses unbounded Python integers throughout.
