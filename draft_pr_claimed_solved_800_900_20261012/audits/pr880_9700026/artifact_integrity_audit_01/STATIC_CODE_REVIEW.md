# Supplied-code review and pin coverage

The four unique Python bodies were read in full before execution. `author/verify.py` and `audit_a/author/verify.py` are byte-identical. All five source paths are included in the outer 40-file manifest; all source JSON and Python bodies were separately parsed before execution. No supplied program imports nonstandard modules, accesses a network, writes corpus/PDF inputs, changes their permissions, truncates them, invokes Git or communicates with a person. The publication wrapper invokes three pinned child bodies using the current interpreter, `-I -B`, and inherited optimization.

The publication-manifest pin externally binds 39 listed files, including all Python bodies, both original ZIPs, both external manifests, all 16 expanded author member paths and all five review-B files; the manifest itself is anchored by the external digest. The supplied outer source manifest additionally binds all 40 files, byte counts and Git blob IDs to the frozen head. Manifest self-exclusion is sound only with the external pin; recomputing and trusting a replacement pin is a new trust decision.

The independent harness starts outside the frozen tree. It hardcodes the supplied outer digest, verifies that manifest first, rejects nonregular entries before opening them, verifies closed file and directory inventories, regular-file permissions, SHA-256 and Git blob IDs, strict JSON (including duplicate keys and overflowing floats), both ZIP payload inventories and type/mode/declared-size metadata, the nested author archive and all readable duplicates, then launches supplied programs. A malicious startup marker mutation is rejected without executing the mutated body. Resealed helper probes always load code from independently pinned original bytes, never from a mutated program.

The harness is an audit tool, not a hostile multiuser execution sandbox. It assumes the independently inspected harness/interpreter/standard library and no concurrent adversary replacing files between authentication and child launch. Its own public manifest will require an external trust anchor before reuse. Raw stdout/stderr capture is not a general redactor; the present receipts are safe because the fixed inspected bodies emit only metadata and paths. TemporaryDirectory cleanup handles normal and exception exits, without guaranteeing crash/SIGKILL cleanup. An explicit allowlist prevents any newly accepted intended-rejection probe from being classified as a passing legacy limitation. It does not create mathematical proof, check present-day literature/priority, authenticate the historical HTTP retrieval events or reproduce GitHub CI. The supplied frozen bytes are the audit target; none were repaired.
