# Independent manuscript-to-Lean coverage audit

Audit date: 2026-09-11 (local project date). Auditor: independent coverage subagent. Completion of this bounded coverage review: 100%. Compilation and semantic verification of individual proof chains are handled separately by the root referee and other independent auditors; a theorem listed here is a checked source statement, not a claim that this subagent personally recompiled it.

## Verdict

The source contains unconditional theorem statements for the central universal two-input convex-hull equality, one-input equality, the 3×2 strict separation, the minimum-input threshold, and Appendix B strengthened attainment. The central equality's final signature is the intended mathematical set equality with arbitrary finite input-dependent output counts; it is not merely a conditional assembly theorem or a numerical test.

**It does not formalize all of the mathematics in the primary paper.** Several named general lemmas and propositions have no exact formal counterpart. Instead, their role in the main theorem is replaced by alternate arguments or specialized consequences. This is an acceptable strategy for certifying the principal results, provided the complete compiled chain passes independent review, but it cannot justify saying that every mathematical statement in the manuscript has been machine certified. The existing `docs/CERTIFIED_COVERAGE.md` already acknowledges part of this limitation; a final report should preserve that qualification.

The most consequential coverage omissions are generic finite POVM dual attainment and its operator KKT pullback; the full weighted Hessian/inertia statement; the explicit 14-dimensional smooth-manifold statement; and parts of the original physical-to-scalar projective-bound route. There is also no generic formal equivalence between arbitrary Hilbert spaces of dimension at most two and the fixed complex 2×2 ambient model, or between explicit stochastic postprocessing and the finite PVM hull. These are interpretation bridges, not hypotheses smuggled into the final equality.

## Central equality and interpretation checks

The actual formal endpoint is:

```lean
theorem two_input_convex_equality (AO BO : Fin 2 → ℕ) :
    convexPOVM ⟨2,2,AO,BO⟩ = convexPVM ⟨2,2,AO,BO⟩
```

`UniversalTwoInputEquality` in `Targets.lean:51` is a proposition definition, but `Assembly.lean:89` supplies it unconditionally. The obsolete conditional helper names in `Targets.lean` do not narrow this final declaration. Its proof calls `counterexample_has_extreme_maximum` and `no_two_input_extreme_separator`; it does not take either theorem's desired conclusion as an argument.

The endpoint is directly elaborated again in `validation/Statements.lean:33` as equality of the two actual `convexHull ℝ (Set.range ...)` expressions. The same contract file explicitly checks a finite mixture of **complete** `ProjectiveStrategy` values, allowing each branch to choose the joint state and all local measurements. It also includes empty-output and zero-input examples. Thus “convexified” does not mean separate mixtures for separate input pairs, and it does not mean topological closure or equality of raw behavior sets.

The remaining conventional translations to the manuscript are:

1. A finite alphabet is represented by `Fin n`; relabeling realizes the usual finite-type isomorphism.
2. Hilbert spaces of dimension one embed in the fixed complex two-dimensional carrier, with unused dimensions assigned to one outcome to preserve measurement normalization.
3. Any finite stochastic map can be decomposed into deterministic maps by weights `∏_a T(f(a)|a)` over all maps `f`. Products across inputs and parties give a single common selector, and summing orthogonal projections implements deterministic output merging. The formal library has the deterministic coarsening pieces, but not this generic stochastic-channel theorem.
4. The real part of the Born trace is the actual real probability because density and effects are Hermitian positive. `Expectation.lean` proves the resulting positivity and normalization, so using `.re` is not a signed/complex surrogate probability.

Items 1–3 are mathematical interpretation arguments, not imported formal assumptions. They should be recorded explicitly when certifying the exact manuscript notation, and may be added as useful formal wrappers if complete model-level certification is desired.

## Runner and axiom-audit trust assessment

Source inspected: `scripts/source_audit.py`, `scripts/check_axioms.py`, `scripts/run_lean.py`, generated `Bell/Audit.lean`, and the declaration inventory.

Positive controls present:

- The runner pins Lean 4.19.0 and the exact Lean/Mathlib revisions, checks tracked dependency cleanliness, invokes valid/invalid compiler controls, moves the local `.lake/build` aside, and performs a fresh production build.
- Both statement-contract files must elaborate successfully. Actual `#print axioms` output is collected from the compiler; each expected public theorem must appear exactly once.
- The allowed axioms are only `propext`, `Classical.choice`, and `Quot.sound`. Missing declarations, compiler errors, `sorryAx`, incomplete-proof warnings, and unexpected axioms reject success.
- Source/configuration hashes are taken before verification and compared afterward. Receipts do not preserve a previous success through a failed run.
- The static scanner strips nested comments and strings, inventories theorem declarations, and forbids common axiom/evaluation/compiler-escape tokens in production sources. It is clearly labeled static, not a Lean parser.

Material trust limits:

- `check_axioms.py` alone accepts a text log. A fabricated log satisfying its format passes by construction; this is not a flaw if it is only used on the runner's real compiler output. A passed archived JSON/log is evidence of a reported run, not an independent proof check.
- The source scanner is a regular-expression inventory, not exhaustive Lean syntax validation. It should not be treated as the soundness boundary. The transitive endpoint axiom checks and genuine kernel execution are what establish proof validity.
- Public theorem dependency checks include private helpers transitively when used. An unused private helper is not separately enumerated in the dependency report. This does not conceal a dependency of the central theorem.
- Dependencies retain prebuilt `.olean` caches. Git revision and `git diff --quiet HEAD` do not verify cached object correspondence, untracked files, compiler binaries, or a compromised cache producer. The runner explicitly records this trust assumption. “All imported source kernel checked” is too broad if interpreted as rebuilding every Mathlib source from scratch; its fresh-source guarantee is for this project's production modules with pinned cached dependencies.
- Version/git-hash strings and smoke tests provide useful sanity checks but are not cryptographic attestation of the compiler. No actual malicious compiler or cache was observed in this source review.
- The snapshot covers production source, validation, scripts, and configuration; it does not bind the entire manuscript/PDF or human semantic coverage analysis. That linkage must come from the separate referee artifact.
- A valid axiom report says nothing about whether a definition or theorem matches its English title. That is why this coverage review and independent semantic chain audits are necessary.

No production source modifications were made by this subagent. No generic duality/Hessian/manifold claims were silently added as assumptions. A useful future improvement is an explicit declaration-level coverage manifest separating exact manuscript statements from replacement proof obligations, with compiled contracts for any presently omitted claim that the project wishes to call machine certified.
