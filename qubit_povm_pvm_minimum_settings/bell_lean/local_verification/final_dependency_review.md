The actual runner uses real subprocesses, verifies the exact Lean version and Git hash, checks pinned package revisions and tracked-file cleanliness, runs valid and intentionally invalid Lean controls, removes the local Bell build directory before the final build, elaborates the independent contracts, executes the generated axiom queries, rejects missing/duplicate/unapproved dependency reports, and compares the source/configuration snapshot at the end. Bootstrap interprets the pinned Mathlib cache acquisition source with Lean instead of invoking an incompatible native cache executable; it does not replace mathematical proofs with a Python calculation.

Normal trusted computing assumptions remain: the Lean compiler/kernel binary and its runtime, Mathlib's pinned downloaded build cache and its producer, the filesystem/process environment, and the reviewed runner code. The project-source rebuild does not rebuild every Mathlib dependency from source. Package revision checks also do not independently authenticate every cached `.olean` byte. Any final statement should say that the **project's Lean source** was freshly checked against pinned dependencies, rather than claim an independently bootstrapped verification of all third-party tooling.

The runner unit tests intentionally mock subprocesses in temporary roots and label their output as tests. Their success is useful evidence about fail-closed control flow; it is never evidence that Lean accepted the paper. Historical JSON reports, cloud preflight reports, and numeric semantic fixtures likewise cannot substitute for the real final run.
