# Independent v1.0.8 software, reproducibility, and submission rereview

## Executive finding

The v1.0.8 repairs to the public replay, direct-verifier assertion guards, PDF semantic check, cubic-recurrence evidence description, immutable release baseline, and output provenance are substantively effective. In the recorded qualification environment, a clean, full (non-quick) public replay completed in **71.69 s** with `PUBLIC_REPLAY_PASS`; all **39/39** direct verifier entrypoints passed normally and all **39/39** failed closed under `python -O`; and all **25/25** tests/mutations passed. Exact data, all simulation-directory files, figures, and manuscript artifacts regenerated byte for byte except for the expected runtime/provenance records described below.

I found three local reproducibility/submission defects:

1. The supplied top-level `release/sha256_manifest.txt` contains **570 paths that do not exist** in the supplied v1.0.8 tree. All of them are stale paths below a prior v1.0.7 audit work directory. The 1,063 present entries all have the correct hash and every actual in-scope file is covered, so this is contamination by surplus historical work-tree entries, not evidence of altered current files. It nevertheless makes `release/create_release_manifest.sh --check` and the top-level replay's baseline gate fail on the tagged tree.
2. `environment/check_toolchain.sh:78-85` deliberately skips the `FORMAT` and `LATEX` rows in the TeX lock. Replacing both expected values with impossible sentinels still emitted `TOOLCHAIN_LOCK_PASS`. Engine, Biber, Python packages, and the remaining TeX packages are enforced.
3. The detached source-package loop in `release/one_command_replay.sh:211-220` compiles `supplement.tex` only twice. A clean two-pass build exits successfully but leaves stale table-of-contents page numbers; one additional pass corrects them and, under the deterministic environment, makes the result byte-identical to the canonical supplement.

These are **minor reproducibility/submission defects** with exact local repairs. They change no mathematical hypothesis, conclusion, equality case, or headline claim. For the software/reproducibility component alone, my category is **VALID AFTER MINOR CORRECTIONS** and my recommendation is **minor revision**. The top-level release-integrity claim must not be presented as passing until the manifest is regenerated and checked on the actual staged tree. The portable public package and journal source contents are not invalidated by that top-level manifest error.

All regenerating work was confined to scratch trees under `agent_software_rereview/`: `disposable_source/`, `public_replay_copy/`, `manifest_negative_copy/`, `manifest_mutation_copy/`, `toolchain_skip_control/`, `toolchain_repair_control/`, `journal_zip_extract/`, `journal_pass_control/`, and `journal_pass_deterministic/`, plus rebuilt ZIP/PDF/log artifacts there. ## Top-level release-manifest anomaly

The supplied `release/sha256_manifest.txt` has 1,633 lines. Independent parsing gives:

```text
present and hash-correct: 1063
present but wrong hash:      0
missing listed paths:      570
unlisted actual files:       0
```

The missing entries occupy manifest lines 639-1208 and every one begins `./independent_referee_audit_v1.0.7_2026-08-22/`. Counts include 199 stale `source_snapshot/repository` files, 199 stale `working_packet/repository` files, 48+48 minimal-verifier files, and 42 rendered-PDF scratch files. This pattern identifies a manifest made while disposable v1.0.7 audit copies were still present, then shipped after those copies were pruned.

In `disposable_source/`, running `bash release/create_release_manifest.sh` created a 1,063-entry manifest and `--check` passed. Compared with the supplied manifest, the repair removes exactly those 570 paths, adds nothing, and changes no common hash. The exact correction is therefore: regenerate `release/sha256_manifest.txt` from the final clean staged/tagged tree, run `bash release/create_release_manifest.sh --check`, then rebuild/check `BUNDLE_SHA256.txt` only if the containing bundle changes. A packaging guard against transient nested `source_snapshot/`, `working_packet/`, and `tmp/` audit trees would prevent recurrence.

Impact: `release/create_release_manifest.sh:8-12` fails now, and `release/one_command_replay.sh:61-67` would fail after the five archive preconditions even if those archives were supplied. It is incorrect to claim that the shipped top-level baseline passes on this tree. The error does **not** affect `public/repository/sha256_manifest.txt`, which passes, or `release/BUNDLE_SHA256.txt`, which passes all seven package hashes. It changes no theorem and does not alter journal source contents, but it should be corrected before minting/finalizing v1.0.8.

## Scope and confidence

Confidence is **high** for the software findings because the public replay was executed from a clean copy with the exact recorded stack, every direct verifier was invoked both normally and adversarially under `-O`, all tests ran, central mutations were independently repeated, PDFs and source ZIPs were rebuilt, and file comparisons were performed independently of project helper functions.

The strongest remaining limitation is not an execution uncertainty but an evidence-boundary issue: many finite regressions and certificate scripts type formulas appearing in the proof, so their success is consistency/mutation evidence rather than an independent derivation of every all-dimensional theorem. The new generic verifier materially closes the recurrence-to-cubic-closed-form bridge but assumes the printed recurrences and formal harmonic sum. The full historical-lineage replay is separately unexecuted because its five external archives were unavailable; this does not diminish the completed portable replay but must remain disclosed as **not checked**.
