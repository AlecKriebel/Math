# Independent software and reproducibility findings

## Bottom line

The supplied exact algebra is substantially executable and mutation-sensitive. The literal required command in the original host environment

```text
bash RUN_COMPLETE_AUDIT.sh
```

exited with status 2 at time 0.00 s because `pdflatex` was absent. This happened before the wrapper's `mktemp` call, so that first invocation created no `WORK_ROOT` and ran none of its numbered stages.

Subsequent disposable TeX environments materially resolve that initial access limitation. With TinyTeX 2026.08 and `pypdf` 6.10.0, the first attempt stopped at the figure stage for a missing `standalone` package; after installing `standalone`, `pgf`, `grfext`, `mathtools`, and their required TeX dependencies, a literal wrapper run reached the final PDF audit and exited 1 on three version-sensitive PDF assertions: a 19-page supplement where 18 was required, a failed positive-diagonal-`D` extraction regex in the main PDF, and the supplement's Latin-`u` phrase check. With the full official TinyTeX 2022.08/Biber 2.18 environment, and again with the release-generation environment TinyTeX 2022.04 (pdfTeX 1.40.24)/Biber 2.17, the literal wrapper executed the minimal replay and all eight repository stages, including every figure and both documents, then exited 1 **only** because `audit_pdfs.py` expected the literal extracted substring `with u the Latin letter`. `pypdf` 6.10.0 actually extracts `withu the Latin letter` from the successfully built 18-page supplement.

A one-condition repair in a disposable work root—replace that literal membership test with `re.search(r"with\s*u\s+the\s+Latin\s+letter", supplement, re.I)`—made the PDF audit pass. The packet source was not modified. This repair changes only tolerance to extractor whitespace; it changes no manuscript hypothesis, theorem conclusion, or headline claim. Therefore the advertised source remains unable to emit its final `PASS` on its own recorded generation environment, but the remaining failure is a **minor reproducibility/software defect (a false-negative audit assertion), not a failed manuscript build or an essential reproducibility gap**.

All separable stages were also run transparently outside the wrapper. The minimal exact replay passed (43.28 s); all 38 advertised entrypoints passed one by one (88.979 s runner time); all 22 tests passed (7.30 s); exact source/manuscript/stale/numerical audits passed; the full, non-quick 15-run simulation campaign passed; exact data, tables, certificate displays, and finite JSON exporters regenerated byte-for-byte; and three Matplotlib figure generators completed. The public PDF semantic audit initially failed to import `pypdf`, then passed on the supplied PDFs when the recorded version 6.10.0 was supplied only through a disposable `/tmp` target.

These passes establish the assertions the programs actually make. They do not by themselves establish the manuscript's all-dimensional theorems. Many entrypoints are finite regressions, duplicate aliases, aggregates, or consistency checks against author-hard-coded formulas. The strongest machine evidence is the exact reconstruction of modulus polynomials/tables, rational comparison identities, low-dimensional matrices, critical kernels, and finite direct harmonic solves. The all-dimensional proof still depends materially on the written derivations.

## Defects and limitations

### Minor reproducibility/software defect: false-negative Latin-`u` PDF assertion

On both TinyTeX 2022 generations, including the recorded TinyTeX 2022.04/Biber 2.17 generation, the complete replay built all figures and both documents and reached `repository/replay.sh:97`. The only failure was `computation/audit_pdfs.py:284,291-292`: it requires the literal extracted phrase `with u the Latin letter`, while `pypdf` 6.10.0 joins the adjacent roman/math glyphs and returns `withu the Latin letter`. The check therefore rejects a document containing the intended wording.

Exact repair: remove that item from the literal-phrase loop and add

```python
if not re.search(r"with\s*u\s+the\s+Latin\s+letter", supplement, re.I):
    failures.append("supplement PDF lacks unambiguous Latin near-threshold parameter")
```

This precise repair passed in a disposable work root. It relaxes only PDF text-extractor whitespace, not required semantic tokens. It changes no hypothesis, conclusion, equality case, or headline claim. Classification: **minor reproducibility/software defect**. Until repaired, the unmodified wrapper's final status remains nonzero even in its exact recorded environment, so `REFEREE_PACKET_COMPLETE_AUDIT_PASS` itself was not reproduced.

### Reproducibility: dependency and engine under-specification

Python dependencies and TeX tooling are not pinned by installable lockfiles. The tested-environment document records Biber 2.17 but omits the TeX distribution generation and package snapshot; independent provenance was needed to recover TinyTeX 2022.04. Modern TinyTeX 2026.08 changed page flow and text extraction, while local Biber 2.22 was incompatible with the Tectonic fallback's BCF. The supplied PDFs were built by a Tectonic/xdvipdfmx route while the replay invokes pdfLaTeX, so byte identity is not a meaningful promised outcome. Classification: **minor-to-moderate reproducibility defect** for portable document rebuilding, not evidence against the mathematics. The exact recorded toolchain did successfully build the documents.

### Software: optimized direct entrypoints can emit false PASS

with their assertions removed. This contradicts `independent_verifier/README.md:31-33`, which says canonical entrypoints fail immediately under `python -O` or nonzero `PYTHONOPTIMIZE`. The orchestrated paths are safe: `RUN_COMPLETE_AUDIT.sh`, both replay scripts, `RUN_ALL_VERIFIERS.py`, and important aggregates set/check assertion mode, and the outer runner correctly rejected `PYTHONOPTIMIZE=1`. Classification: minor software/reproducibility defect in direct-entrypoint behavior; it did not invalidate this campaign.

### Reproducibility: final manifest is self-generated

`repository/replay.sh:107-111` rewrites `sha256_manifest.txt` from the just-generated tree and then checks that new manifest. A mutation correctly fails against the downloaded manifest but passes after these lines rewrite it. The outer wrapper's initial manifest check protects pristine input, and its last check protects against changes after replay, but there is no fixed baseline comparison between supplied and regenerated artifacts. Classification: minor reproducibility/interpretation defect; the final `sha256sum -c` proves internal self-consistency, not reproduction of the release bytes.

### Evidence scope: exact, finite, and hard-coded layers are mixed

Several outputs named `PASS` are finite exact regressions, and the two spectral scripts are floating regressions. Critical all-m formulas (`w_0`, `w_2`, `N_formula`, `Q3`, Pareto/gauge polynomials) are hard-coded in shared author source, then checked directly only at selected dimensions. Generated sign tables and exposition verifiers often retype the same literal formulas; this detects transcription mutation but does not independently derive them from the indexed reactions for symbolic `m`. The software honestly notes this in several docstrings and in `CERTIFICATES.md`, but a referee must not read aggregate passes as theorem proofs.

### Evidence scope: duplicated and aggregate entrypoints

The minimal verifier is a byte copy, eight `dd_`/non-`dd_` pairs are semantically duplicates, and four entrypoints merely rerun children. The “38” count demonstrates replay coverage, not independence. This is not a failure, but it lowers the evidentiary weight of a raw pass count.
