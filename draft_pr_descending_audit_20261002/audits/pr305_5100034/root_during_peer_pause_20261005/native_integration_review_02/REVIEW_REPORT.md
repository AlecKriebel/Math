## Required R02-M1: contain errors throughout completed capture

**Priority P1.** The broad exception boundary covers Popen, the started-record write and `communicate`. It ends before the completed stdout/stderr compression, exclusive file creation, fsync, storage round-trip verification, completed execution-receipt write, completeness check, exit-code check and return. An exception in any of those later operations bypasses `contain()`.

This is materially distinct from the repaired started-record failure path. A native parent can exit normally after spawning a cooperative descendant that remains in its process group but closes its inherited stdout/stderr. The parent's `communicate()` then returns successfully while the descendant is still alive. If a completed stream or receipt cannot be saved, this candidate unwinds without killing that group. A Git hook or transport helper with closed capture pipes is a relevant mechanism; the test does not require a process that escapes its session or process group.

The defect was reproduced first by `independent_driver.py`, then by the separate `native_capture_observer.py`. All writes and subprocesses were confined to this review namespace. No Git executable, network client, Zenodo, GWS, production lock or reservation was invoked.
