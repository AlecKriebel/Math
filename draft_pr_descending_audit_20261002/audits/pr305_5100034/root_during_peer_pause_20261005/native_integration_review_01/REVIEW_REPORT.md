## M1 — enforce fresh lease coverage at every actual write

**Required, P1.** Candidate lines 74–78 check the lease deadline before `safe_endpoints()` and `stable()`. Those readbacks can take time, and there is no deadline recheck after them. The operator can therefore return from `authorize()` with an expired lease and launch a genuine writer. The placement also leaves grouped mutations uncovered: lines 85–89 merge, read conflict state, write QUEUE, add QUEUE, create/write/chmod four new files and add those files under one earlier authorization. Lines 95–96 authorize, run ancestry and remote-main readbacks, and then push without a fresh launch-time check.

This is not a hypothetical source editor or concurrent hostile writer. It follows from the permitted command timeouts and an otherwise stable cooperative repository. A bounded lease is an execution condition, so slow ordinary reads are relevant even when the exact expected hashes and heads still match.

`adversarial_controls.py` executes the exact extracted candidate AST blocks against a virtual clock and fully synthetic repository/services. It reproduces three controls in `COUNTEREXAMPLES.json`:

1. An authorization starts with 100 seconds remaining, passes its 60-second check, and spends 110 seconds in the endpoint/stability readback model. It returns normally at virtual time 110, after expiration. The following writer would be launched outside the lease. The stability function comprises several independently bounded native readbacks; the model does not require a single child to exceed its permitted timeout.
2. Authorization starts with 100 seconds remaining. The exact block accepts a push that completes at virtual time 110, after expiration.
3. A merge takes 55 seconds and the conflict readback another 55 seconds. The shared QUEUE body write and both `git add` invocations occur at virtual time 110 under the originally valid 100-second lease. No per-write authorization intervenes.

The clocks and service/Git calls in the controls are explicitly mocked; this is not a claim that a real shared writer ran after expiration.

**Repair needed:** perform complete validation first, then re-read the exact lease/shared controls and recheck sufficient remaining deadline immediately before every actual writer. Put a launch guard inside the native mutator wrapper so fetch, PR edit, merge, add, commit and push cannot bypass it after intervening reads. A passing initial or grouped authorization must not remain authority after arbitrarily long subsequent reads.

## M2 — contain the complete cooperative native process group

**Required, P1.** Candidate lines 33–36 start a child without a new process session, kill only that child on timeout, and then invoke `communicate()` again with no timeout. A Git transport/helper can be a descendant. Killing the Git parent does not guarantee that a surviving transport stops its remote write or releases inherited pipes. This defeats the stated 55-second bound and can permit continued mutation after the lease expires.

This mechanism was reproduced with real native benign processes in `optimization_guard.py`; no Git binary, network request or production program was used. The exact nested capture function was extracted from the candidate AST. Its sole timeout literal was scaled from 55 seconds to 0.2 seconds to make the test fast; all timeout/kill/second-communicate control flow was unchanged.

The benign parent PID **12917** spawned descendant PID **12918** inheriting the capture pipes. At the scaled deadline the candidate killed only the parent. The descendant remained alive, completed a toy file write confined to this review namespace, printed its completion, and exited. The capture returned after **0.6247671250021085 seconds**, substantially beyond the 0.2-second deadline, with the candidate's timeout outcome code 124. `DESCENDANT_COMPLETED_AFTER_PARENT_KILLED.json`, the exact actual capture argv/cwd/PID/times and complete gzip streams are preserved under `native_guard_cases/process_tree/`. `NATIVE_GUARD_AND_PROCESS_TREE_RESULTS.json` records the bindings. The outer genuine review process PID was **12912**, exit 0. All native children had completed before closure.

Ordinary SSH or remote-HTTP helper behavior is the relevant class of descendant; this is not a claim about malicious processes that deliberately escape a process group. A cooperative Git writer must have a bounded containment path.

There is a second source-level path through the same gap: after `Popen()` succeeds, an I/O error writing the started receipt at line 34 is not caught by the `TimeoutExpired`-only handler. The already launched writer is then left running without bounded cleanup. The native witness above tests the timeout branch; the I/O branch is established by direct control-flow inspection and is not presented as an independently injected native disk failure.

**Repair needed:** start each captured command in a new session, kill and reap its entire cooperative process group on timeout, and bound stream draining/reaping. Ensure cleanup also occurs on any exception after native launch, including capture I/O errors. If complete streams or cleanup cannot be established, explicitly preserve an incomplete/uncertain outcome and fail without retry. The per-write lease must cover the command deadline and this cleanup/capture margin. This repair can contain local helpers; it cannot undo a remote mutation that already completed, so the permanent attempt marker and read-only reconciliation rule must remain.
