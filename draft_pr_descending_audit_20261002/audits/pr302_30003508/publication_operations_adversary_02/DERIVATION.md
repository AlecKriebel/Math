# Reconstructed publication invariant

Let C be the fixed revised candidate manifest, E its23 file pins, S the genuine ROOT science decision, Q the externally pinned four-program registry, O the future genuine ROOT operations decision, and V the five named fresh-review artifacts. Let B be the three resolved binary pins. For the current clearance() to return, its necessary clauses establish C's hard-coded SHA and S.candidate_manifest=pin(C), each e in E equal to its current literal file/body/mode0444, the14 named accepted science inputs equal to current bodies/modes, actual ROOT mathematics acceptance for both rounds, and local metadata/upload scope equality. It also requires O to bind S,C,Q; Q must enumerate precisely four unique current source pins, O must equal those pins, V must belong to a fresh namespace with an empty-issue non-authority verdict, and B must enumerate precisely Python/curl/Workspace. Thus an empty evidence list, an arbitrary narrower voluntary pin list or an unreviewed source version cannot satisfy this contract.

For a captured process, execute() checks this contract before constructing evidence, before Popen and after successful completion. It archives all four program bodies and, where used, the kit body; all three approval/registry bodies; observed resolved child/caller target pins; request/argv/cwd/time and actual recorder PID; the observed child PID/start marker; actual terminal exit/timeout; and both complete gzip streams with stored/logical pins. authenticate_execution() repeats clearance, exact endpoint/argv/cwd, request/result agreement, positive integer PID observations, exact started marker, timezone-aware ordered times, successful non-timeout/nonretry outcome, binary targets and exact complete source/approval arrays. It compares every retained archive's entire logical body to its current pinned input and every full stream to stored/logical pins. This is a recorder-custody implication, not a mathematical proof of OS or external-service truth; its stated limit remains essential.

Published inspection requires the production record, exact reviewed title/state, positive exact record ID and consistent DOI/record URLs, precisely two names and each local size/SHA. It then authenticates the actual inspect argv/capture and requires its full stdout JSON equal that receipt with empty stderr. A free-standing label or unrelated inspected paper cannot satisfy it. The anonymous verifier requires the same inspected publication, a complete public declaration, exact API-read native receipt and full raw metadata. Its map preserves every local field, translating only license.id and resource_type.type/subtype. It requires both exact content endpoints and reconstructs each complete anonymous download, comparing bytes with the frozen candidate, remote size/MD5 and the complete corresponding native/file declaration. A consistent replacement of receipt hashes cannot hide changed title, identity, metadata or file bytes because the independent fixed candidate remains the comparison anchor.

The tracker invokes the preceding implication before its first service call, and again after dry run immediately before its sole append. Its current metadata selects the exact spreadsheet/GID/tab and all columns; prior table/header/duplicates are checked. After append, shape, exact returned row and whole prior table plus precisely that row are required for completion. A thin declaration fails before transport; a changed declaration after the initial check fails before append; a concurrent prior-table change fails completion after append. The third case is deliberately not called rollback or transactional isolation. Unique capture paths and uncertain markers require read-only reconciliation rather than a repeated mutation.

For the repository kit, the saved production ID is checked against --confirm-id and the complete current metadata/size/MD5 before publish. An already-submitted record returns without POST. A draft receives one POST, followed by readback even if the POST response was lost. Confirmed submitted identity and exact content yield one confirmed receipt; unavailable or unsubmitted readback stops. The actual mock observations corroborate zero/one POST counts and never infer a live Zenodo outcome. These invariants cover the repairedG1/G2 findings without transferring a central evidence requirement into an unsupported status string.
