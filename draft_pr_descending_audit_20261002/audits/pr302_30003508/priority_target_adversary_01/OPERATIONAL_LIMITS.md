# Honest operational record

The native source/scientific-control record consists of each retained execution.json and its exact launcher/stdout/stderr. Failed fetches remain failed. Read-only text inspection commands and web-tool responses are not promoted into fictional native controlled executions.

An auxiliary inline Python page locator failed with FileNotFoundError for private_sources/ren_arxiv.txt; the actual extract was private_sources/ren.txt. The tool returned exit1 and the full failure in the conversation, but did not expose the actual child PID. It is not part of a scientific control result, and no PID or success is invented for it. The command had already preserved an earlier research-log timestamp before failing; that preserved original remains under timestamp_corrections.

The initial independent assessment incorrectly stamped a future 05:00UTC checkpoint. Its original bytes are retained; correction binds the actual original file creation modification time 04:51:10.944861UTC. Four earlier web-response serializations carried an approximate future 04:50 stamp; originals and their original modification times are retained, and the corrected records explicitly label local serialization time rather than native search time. A subsequent log entry was written as 04:57 while its own operation emitted 04:56:16.240861UTC; its original is retained and corrected to that actual operation time. The correction manifest and originals preserve the distinction between scientific content and clerical timestamp repairs.

One parent status message estimated actual time as 05:08; a subsequent clock returned 05:06:26. This estimate was corrected to the parent and is not source-custody evidence. Model-capacity interruptions reported by ROOT are operational interruptions; neither is counted as an independent completed scientific review. No old failure record is overwritten to claim success.

Frozen initial priority criteria retain their original contents and mode 0444. Native capture records retain their historical source/stream modes. Final family permissions are recorded separately. Final output inventory deliberately excludes itself and the three closing stream/receipt files to avoid circular hashes; the closing execution separately binds the inventory and its actual complete child streams. Independent hashes of these excluded files remain available to ROOT.

Native runtime pins bind the complete executable files, retained launcher source and the selected standard-library modules named in each receipt. They do not claim a complete dynamic-library, OS, compiler, environment or import-closure capture. The closure control compares those exact retained pins and current whole-file bytes; it does not retroactively expand the earlier runtime evidence. This limitation affects custody completeness, not the independently read mathematical model and theorem comparisons.
