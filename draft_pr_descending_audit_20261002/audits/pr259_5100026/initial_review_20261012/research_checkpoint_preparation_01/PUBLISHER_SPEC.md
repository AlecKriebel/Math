# Inert standalone publisher specification

NOT_AUTHORIZED. No publisher is implemented or run by this preparation. This specification is review material only and must not be treated as an action token.

1. A future fresh standalone publisher may read only the frozen payloads and exact pinned plan files. It must not import, execute or replay prior PR261 publication stages. Root's explicit one-stage GO must bind repository, exact Main expected-old observation, source manifest hash, selected-target manifest hash, tree plan hash, raw commit hash, publisher code hash, and a single bounded stage. Absent or stale bindings fail before any write. The stage must not claim ownership over unrelated writers.
2. Capture every request body, endpoint, method, raw stdout/stderr, exit result and UTC interval. Immediately before any object creation, read Main and the native commit/tree, and require exact match with the reviewed baseline. Reverify all frozen input byte counts, SHA-256 and native OIDs; do not consult changing live files as payloads. Construct only absent/changed blobs and bottom-up nonempty trees with the reviewed full immediate child entries. Verify every returned object OID and re-read its bytes or native tree.
3. Build a single unsigned commit with the exact reviewed tree, sole parent equal to expected-old Main, identity/date fields and message. The canonical preimage must have no terminal LF. Verify the complete returned Git commit object against that preimage and native OID; checking only tree and parent is insufficient. Do not accept provider normalization of reviewed bytes silently.
4. Re-read Main immediately before the sole ref update and require expected-old equality. Use an update interface with atomic expected-old comparison and force=false where available. GitHub REST PATCH supplies force=false but no explicit old-SHA field; its fast-forward guard plus the direct reviewed parent prevents the normal competing-descendant race, but is not a literal arbitrary-state CAS. The final publisher must explicitly document this limitation and use a true expected-old transport if Root's GO requires literal CAS. Never claim atomic expected-old semantics from an earlier GET alone. A mismatch aborts; no automatic retry or rebase. Ref rewind races cannot be excluded by read-then-PATCH alone.
5. After one successful update, independently GET Main, the entire actual commit and every touched native tree/blob; validate full canonical commit bytes and the semantic diff. Write COMPLETE only after exact source, object, preservation and postread checks pass. A partial failure is evidence to inspect, never authority to replay. Any recovery requires a fresh Root decision and plan.

Permitted intended effect, subject to future exact authority: one nonfinal owned research-findings commit on Main. Forbidden effects: operative QUEUE change, author branch, PR title/body/status, merge/closure, paper, Zenodo/DOI, tracker, release, excluded-status processing, global scope/log replacement, or changes outside the exact selected targets. Publication of checkpoint evidence does not provide theorem or priority clearance.
