# Private editorial adapter contract

Input is the fixed SOURCE_INPUTS seal, static EDITORIAL_CONFIG and the entire PUBLIC_MAIN. Output consists of a private head, standalone candidate HTML, unchanged original PDF/ZIP, BibTeX, plain editorial copy and scholarly JSON-LD. Normal and optimized runs write two separately named finite output directories once; their exact whole result buffers must agree. No body transformation is applied to PUBLIC_MAIN. Head markup escapes all ordinary metadata and JSON-LD escapes less-than characters.

No installed renderer, native or archived scientific programme, old fault campaign, browser server, dependency installation, subprocess or network request is part of the adapter. All writes are exclusively created ordinary files below one of the two declared new output roots. It cannot install into a website or modify a tracker. No canonical link is emitted; only a private slug proposal is retained in config. Bibliographic and citation PDF URLs identify the already published Zenodo reader.

Default custody verification uses only Python standard-library imports and reads. It authenticates and parses the same seal/manifest buffers, checks all exact ordinary file and directory extents, preserves whole source/root/scientific/core bytes, and rejects symlinks, FIFO/special entries and undeclared empty directories. The only final exclusions are the exact root terminals OWNED_MANIFEST.json and FINAL_SEAL.json, themselves explicitly required when sealed. There is no runtime or future-prefix exemption. The renderer has no post-seal invocation authority; valid final custody is entirely read-only.

Normal execution checks are primary. The separate optimized run demonstrates that the controls use explicit exceptions rather than assert statements; it is not a new mathematical proof. Static copy checks are bounded loss controls and do not replace root editorial reading or independent fact review. Stable filesystem/cooperative writers are assumed; this is no OS isolation or race-proof snapshot claim.
