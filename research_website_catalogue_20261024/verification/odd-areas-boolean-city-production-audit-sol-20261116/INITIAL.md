Private adoption gives no installation, Git, deployment or tracker authority. Default/preflight must be actually read-only, including avoiding shared-index refresh, transaction locks, journals, temporary indexes, Git objects and network activity. Installation and Git publication need separate concrete root authorities bound to the actual helper, PLAN, baseline, adopted stage and payloads. Historical success objects and retained completed locks cannot authorize a new transaction.

Before the first website write, the mechanism must authenticate all source buffers and hold the validated bytes, durably retain both old aggregates and record all 16 new-path absences. It must protect the full public baseline and existing directory modes. Exclusive creation must prevent a newly appearing path from being overwritten; aggregate replacement must check the expected old bytes. Each replacement may be atomic, but an 18-file transaction is not globally atomic. Partial failures must retain truthful phase information, backups and partial outputs. Recovery must avoid overwriting third-party edits or removing unrelated/nonempty directories. No broad Git cleanup or automatic foreign-ref rollback is acceptable.

The current W lease is the actual 8db8 index, 9,049,366 bytes, mode 0644, against master f632 and tree 7d5180. The earlier 0f58/0600 observation is historical and cannot be silently restored. The native successor must contain 58,667 entries while preserving all 58,649 untargeted current whole raw entries, including their stat cache, OID, mode, path, flags, stages and padding. New/replaced target entries must have correct byte lengths, sorting, mode, stage and checksum. Parsing must reject unsupported formats and unexpected extensions rather than normalizing foreign entries. Preserve M local main/HEAD and native index; harmless origin/fetch metadata changes do not imply M local main changed.

The current sole TREE region is derived data. Root's current explicit requirement supersedes earlier exact-extension wording: TREE may be dropped, invalidated or rebuilt coherently, with no other extension changes. Preserving a valid stale cached descendant can return an old tree even when target raw entries changed. Invalidating only the root while retaining an incorrectly valid changed descendant is also insufficient. The actual private write-tree and the installed native index must have coherent scoped semantics; evidence must distinguish raw-entry identity from cache-derived tree identity.

There are two separate preservation obligations. The commit must have exactly 18 path changes, 16A/2M, against f632, preserving every untargeted HEAD-tree entry. The native successor must preserve every untargeted staged raw record. If an unrelated staged OID differs from HEAD, writing the entire current index as the commit would sweep foreign staging into the commit; resetting a native successor from HEAD would lose it. The code must explicitly satisfy both obligations or fail closed on a concrete incompatible precondition. A tree comparison solely to another result derived from the same stale cache is not independent evidence.

Publication must compose an exact single-parent commit and CAS the existing master, preserving the native index mode through an atomic locked replacement with durable receipts. Ref and index changes are not one global atomic operation; failure phases and permitted recovery need to be explicit. Creating a private Git object is not publication. Only a concrete immutable commit-to-master nonforce push may be authorized later. Intended remote routing must be pinned, effective push URL must be a singleton, and effective pushurl/rewrite/include/environment routing changes must fail closed before remote commands. Credential helpers should remain available; they are not a reason to disable legitimate authentication wholesale. Remote advancement or ambiguous push results cannot become a silent success or force retry.
