## Concrete concurrency findings

These are reproducible windows, not claimed full-installer bypasses. `audit_controls.py` executes only selected pure library function definitions and isolated memory/filesystem fixtures in this audit directory. It never imports/runs the installer or invokes Git. The initial control harness omitted a standard-library binding, failed with `NameError`, and was corrected; its initial stderr is retained. The final controls pass.

1. **Seal verification parses another read.** `exact11_lib.py:144–145` hashes one `FINAL_SEAL` buffer and then `obj()` reads it again. The memory control interleaves an authentic first seal with a different second seal and manifest; the actual `sealed_namespace` function accepts that substituted packet. Similar rereads of previously verified plan/overlay/input manifests rely on continued packet stability. Parse the authenticated bytes and retain authenticated manifest/contract buffers to reduce these windows. This control establishes the primitive's stability assumption; it does not establish an end-to-end bypass of the later exact path, payload, authority or count checks.

2. **The validated alternate index is later consumed by mutable pathname.** `install_exact.py:144–165` parses/checks `newraw`, then later opens `shared-index.approved` only to fsync it and replaces the real index from that pathname. A writer can change that file after validation while still respecting the real Git index lock. The isolated control installs bytes different from the checked buffer using this exact check/fsync/replace sequence. Use the validated `newraw` buffer to write the owned lock descriptor, fsync it, verify the owned lock directory entry and rename that owned inode into the index, or explicitly require exclusive stable runtime custody. A final reread alone narrows but does not remove the pathname race.

3. **Lock cleanup follows symlinks.** `install_exact.py:185–188` compares `lock.stat()` with the owned descriptor. A substituted symlink to a retained hardlink of that same inode passes the check even though the lock directory entry differs. The control demonstrates this case. `lstat()` plus regular-file/inode checks identifies the entry directly. This requires a noncooperating writer replacing the lock; ordinary cooperating Git writers do not do so.

4. **Aggregate check/replace and path checks require cooperation.** The already disclosed `pin(dest, baseline)` followed by `os.replace` can overwrite an edit made between the two calls; the isolated control confirms it. Destination ancestor checks and `read()`'s real-path checks are also check-then-use operations, rather than descriptor-relative race-resistant confinement. The no-clobber `os.link` for a new leaf correctly preserves an existing destination under stable ancestors. These mechanisms are adequate only with stable destination ancestors and no concurrent noncooperating writers.

No source was changed to address these observations. If adversarial/concurrent local mutation is in scope, findings 1–4 are gaps and this audit does not approve execution. If root adopts the stated stable namespace assumptions, these are qualified limitations rather than blockers; root must not describe the preparation as race-resistant or hermetically immutable. Root retains the choice whether to require a new sealed revision before adoption.

## Verified safety mechanisms and limits

The explicit `--execute` gate and whole-hashed, fixed-path actual root receipt are checked before mutation dispatch. The template has literal false authority flags, a null preparation seal and a template marker; boolean checks reject integer substitutes. Current pair seal paths/hashes, all six code bodies, exact11 path order, baseline/candidate counts, full preparation, original shared-index bytes and protected-record hash are tied to the future actual receipt. Historical packet flags remain unchanged. The current standalone library is inert at import; no supplied writer, independent auditor, renderer or scientific helper is executed by preflight.

Nine leaves use a fsynced sibling buffer and atomic no-clobber link. Each aggregate checks its exact baseline bytes immediately before its atomic replacement. Whole installed scope, paired payload bytes, all 603 unrelated public files, bound source/editorial namespaces and site/config inputs are rechecked. Installation is eleven separately atomic operations, not one transaction. Failure after any leaf/aggregate leaves a partial working tree and `run-state` that deliberately blocks automatic repetition.

The temporary commit index is newly seeded from immutable checked BASE, not the shared index. Unfiltered blob IDs, exact modes/paths, sole actual parent and the whole commit diff are checked. The separate root commit approval pins the pending receipt and the actual immutable commit/tree; publication revalidates the complete exact11 diff and derives index entries from that commit, not `commit.index`. The pending-receipt reread cannot substitute a different effective commit without failing the separately compared approved parent/commit/tree/path fields and immutable commit checks.

Native v2 protection includes stat fields, mode, OID, ordinary flags, path and zero padding; malformed/checksum/version/unmerged/extended entries and unsupported extensions fail closed. Exact protected raw records, rather than only staged tuples, are compared before real shared-index replacement. The isolated control changes a protected stat byte, recomputes the native checksum, preserves every staged tuple, and demonstrates that the raw-record guard detects it. Exactly nine new entries and the exact approved eleven target records are required. The TREE cache extension may change; the preserved claim concerns protected entry records, not whole post-publication index identity.

The real shared-index expectation is rechecked under an exclusive `index.lock`; an existing lock is not removed. Local `update-ref` explicitly compares old BASE. Index replacement and ref update are separate operations: a CAS failure can leave the new index with the old branch, and a push failure can leave the new local branch with old or uncertain remote state. A crash or timeout may leave stale owned locks, temporary files, partial receipts or an already-updated remote. There is no automatic rollback/retry/repair. Parent directories for public additions/replacements and ordinary receipts are not all fsynced, so crash-durable all-or-nothing publication is not established. Root must inspect actual state after any failure rather than repeat a phase.

The sole push uses one explicit commit-to-master refspec, without force, tag following, mirror or submodule expansion. The sealed pre-push hook verifies exactly one update, the approved new OID, master, expected actual push URL and actual advertised old BASE; receive-pack then applies its old-OID check. Pre/post remote reads use the explicit actual push destination. Git's ordinary cooperating lock and immutable-object semantics are assumed. Effective global configuration and the Git executable are part of the trusted execution environment; only the local config bytes are baseline-pinned. Deployment, live/browser/native-Sheet checks, redirects, canonical URL and AA remain outside this audit's authority.

Strongest result: current sealed preparation is internally consistent and matches the actual old baseline, with correct narrowly scoped mechanisms under the explicit stability assumptions.
