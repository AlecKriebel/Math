## Invariants and concrete falsifiers for the eventual complete body

1. **Default and error lifecycle.** The ordinary default must be genuinely
   read-only and offline: no W/public/config/Git-object/index/ref change,
   no auth consumption, lock/journal creation, repair, deployment, remote
   lookup, source replay or hidden mutating branch. Unknown flags, missing
   scope, missing/mismatched authority, expired state or partial recovery
   state fail closed before such effects. A successful static read is not
   a runtime receipt. No first execution is authorized by this INITIAL.

2. **Actual source adoption.** Root adoption must bind the actual closed
   finite stage FINAL/manifest, independent integration closure, exact page
   set and all candidate/source pins. The implementation must compare their
   actual bytes, status and false-action-authority semantics. A convenient
   expected schema, a writer READY, a preparer's PLAN, old successes or
   unresolved third-page proposal cannot create authority. Row162/163's
   original editorial adoption (parent supplied ca6f45fd, 10,294 bytes,
   verification/root-162163-editorial-adoption-20261116.json) permits only
   that private stage, not production. The parent reports a row166 writer
   FINAL 07afb343/48 files/2 directories, with fact/root-copy adoption still
   pending. Those supplied references were NOT opened or authenticated at
   this gate. No row166 bytes enter the permitted payload by inference.

3. **Separate execution authority.** Fresh root filesystem-install and Git-
   publish permits must bind the current code/PLAN/adoption, exact finite
   payload, baseline fingerprint, permitted action and unique transaction.
   Nonces must be fresh and single-use. Validate current time, expiry and
   identity before side effects and immediately before each remote action,
   including final ls-remote. Long scans cannot be treated as keeping a
   previously checked permit fresh. Installation cannot imply Git, and Git
   cannot imply deployment, redirect, tracker or source-edit authority.

4. **Locks and journals.** Isolated new lock names must not collide with old
   retained markers. Creation must be exclusive and identities held, not
   inferred from a path check. Bind nonce/owner/inode or equivalent identity,
   expiry and action. No stale/completed lock deletion, silent takeover,
   automatic retry, rollback, cleanup, resume or reuse of an old permit.
   Durably journal intent before each irreversible boundary and completion
   afterwards. fsync buffers, backups, relevant files and directories as
   needed. A journal parse error or interrupted/ambiguous prior state stops
   for concrete disposition; preserving evidence is not automatic recovery.

5. **Exact filesystem transaction.** Once scope is fixed, authorize only a
   finite exact path set; separate new leaves from existing aggregates.
   Preserve all 118 old visible items and whole typed ListItems, all 119 XML
   nodes, and every untargeted public buffer/mode/path. Counts alone cannot
   prove preservation. Native assets, Bibs and adopted MAINs must retain
   exact source bytes/order. Buffer ALL approved payloads durably and back
   up exactly the existing replacements before the first W write, retaining
   full public-relative backup paths and original modes. Record absent new
   targets and create only necessary approved folders. New leaves require
   exclusive creation; aggregate replacements require per-file atomic rename
   and held-identity checks. There is no global multi-file atomicity claim.
   A partial install retains exact journals, buffers, backups and observed
   installed subset; it does not publish, continue, retry or roll back.

6. **Namespace and race boundaries.** Reject source/target/ancestor symlinks,
   nonregular files, path escapes, ambiguous case/normalization collisions,
   duplicates, nested/prefix collisions and unexpected namespaces. Verify
   actual source and W identities when used, not just at a distant scan.
   A source changed after preflight or a leaf appearing before creation must
   fail closed. Do not normalize the existing 0750/0755/0777 directories or
   0644 native index to an inherited template. The baseline's absence of
   public symlinks is an observation, not a guarantee of future safety.

7. **Native index and staging semantics.** All 58,667 current native records
   are frozen inputs while target membership is pending. Later exceptions
   can cover only the exact approved targeted entries; all untargeted raw
   record bytes, stat fields, flags/extended flags, object IDs, stages,
   modes, path bytes, ordering and padding must remain exact. Do not confuse
   a HEAD comparison, ls-files --stage output or porcelain cleanliness with
   full native-index preservation. Preserve every extension except an
   actually necessary derived TREE adjustment, justified by a private
   semantic comparison. Unsupported/required extensions fail closed; no
   silent extension drop or canonical rebuild. Full index version/checksum,
   entry semantics and all non-TREE extensions need an explicit proof from
   actual bytes. Compare the entire protected record set, not samples.

8. **Private commit index and HEAD separation.** Build any commit with a
   private index and exact one-parent tree. Preserve all untargeted HEAD
   tree entries independently of shared-index state, and preserve unrelated
   staged/intent-to-add/skip-worktree/assume-unchanged/unmerged semantics.
   Scope GIT_INDEX_FILE only to the private command; never point a broad
   restore/checkout/read-tree at the shared index. A raw successor index,
   if approved, requires its own semantic proof and atomic held-identity
   update, not arbitrary serialization of the stage listing. Shared index,
   local HEAD/ref and worktree are different guards. Math HEAD/main and
   index remain exact throughout.

9. **Git destination and immutable publication.** Keep actual fetch/push
   destination resolution and an opaque relevant effective-config pin
   immediately around EVERY remote action. Require the exact authorized
   singleton route; reject effective origin.vcs, alternate transport/helper
   selectors, rewrites or relevant config drift. Check expiry after costly
   local scans/routing and as close to the action as possible. Compare the
   exact authorized remote parent; create one commit with that one parent;
   push the immutable commit ID to the exact scoped branch without force.
   Never push ambient HEAD/main/master by convenience or sweep unrelated
   staged changes into the commit. A remote mismatch/race or ambiguous
   push outcome stops without retry or reset. Final remote identity checks
   require the same fresh authority and routing fences. No deploy action
   belongs in this adapter merely because publication succeeded.

10. **Finite evidence and bounded audit.** Every claimed pass needs actual
    body/byte evidence, with literal errors/exit streams and access limits.
    The eventual complete current helper/PLAN/docs and exact reference delta
    must be personally read after a fixed handoff. Only then, if necessary
    and concretely authorized, one own fully read read-only data utility may
    compare bytes/semantics. No old helper replay, broad fault framework,
    compiler/import/AST run, hostile writer or test campaign. Any unexpected
    real guard failure stops and is reported. Root will personally review
    actual code and operate preflight/install/Git/deploy under fresh GO.
