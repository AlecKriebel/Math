# Retained failure state and recovery inputs

No action or recovery has been run. The helper supplies journals and durable recovery inputs; it does not automatically roll back, retry, release locks, reset a branch, clean files or overwrite another writer's work. Filesystem install, local Git publication and remote push are separate phases. This is deliberately not a claim of global atomicity.

Before any W mutation, all18 buffers are fsynced and held, both original aggregates are held and backed up under backups/<full-public-relative-path>, sixteen full-relative target absences are durable, and rollback.before.json records the original aggregate pins/modes, new target absences, four directory absences relative to public, and original shared-index pin. The full old public/Math/index/source/config fence is repeated. Each directory creation and atomic leaf/replacement has an intent and completion journal entry, followed by identity/bytes/mode and directory fsync checks. Failures before first W write leave private preparation and retained locks only. Failures afterward may leave a valid prefix of new files or one replaced aggregate. Stop: root must compare the exact journal, current file identities/hashes and backups before separately authorizing completion or path-specific restoration. Never delete or restore merely because a name appears in a plan.

Git records the original whole native index and uses fresh native-successor, commit, before-semantic and after-semantic private indexes. Before CAS, a failure can leave objects, private indexes or an owned shared index.lock; keep all evidence and the exact lock identity. It must not be confused with an old completed ACTIVE lock. The journal distinguishes commit-object creation, CAS_REF_INTENT/COMPLETE and INDEX_ATOMIC_REPLACEMENT_COMPLETE. CAS can have succeeded even if a subsequent operation fails; local ref and native index are separate atomic operations. Root must inspect actual branch/index/lock state before a new authorization; there is no automatic reset or blind replay. If index replacement completed, its exact current bytes/mode and raw records must be compared before any recovery proposal.

After local success, remote failure or lost response is ambiguous: a nonzero/error response does not prove that push had no effect. The immutable intended commit and exact branch are in the journal. Root separately authorizes bounded remote verification before any decision; no automatic push retry or forced ref update exists. Even a successful remote push followed by final-local or receipt-writing failure retains that history rather than inventing a clean success.

Old and new ACTIVE_INSTALL/ACTIVE_GIT locks are retained. No cleanup, lock release or source/production mutation is authorized by this packet. A manual recovery proposal must bind actual current evidence and receive separate root authority. ROOT_SERIALIZED_NO_OTHER_W_WRITER is an explicit action precondition, not a guarantee against hostile external processes.
