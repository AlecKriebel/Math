# Retained state and bounded recovery

The transaction is not globally atomic. Each individual file publication is atomic, but the 22 files, three directories, local branch ref, native index and remote branch advance at distinct phases. A failure can leave an installed prefix, a new ref with the old index, an index lock, a local commit not pushed, or a push whose remote result is unknown. The helper stops and retains the exact partial state; it does not retry, remove locks or perform automatic rollback.

Before the first website write, installation stages and fsyncs all 22 held candidate buffers, writes and fsyncs the two original aggregates beneath backups/public/research/, records all 20 original new-leaf absences and all 3 original directory absences, and durably writes rollback.before.json. It repeats the whole authorized baseline fence after those preparations. Exclusive Darwin rename prevents an added leaf from overwriting an intervening file. Aggregate replacements require the held original inode and complete durable backup bytes. Each rename and relevant directory is fsynced. Source/website types, modes and topology are checked; no symlink is followed. Existing files outside the two aggregates are never replaced.

If failure occurs before any W mutation, retain the transaction lock, staged files, backups and journal. If failure occurs after one or more writes, freeze all further W writers and record exact observed files, modes, directory identities, native index, HEAD, source and remote state. The completed_targets journal field is evidence only; inspect live bytes and inode identities as well. Do not run the same helper again, infer success from a partial aggregate, or delete locks to bypass exclusion.

A later recovery requires a distinct root decision and a concrete reviewed scope. An aggregate can be restored only from its exact mirrored backup after current ownership/bytes/mode checks. A newly added leaf can be removed only if it was originally absent and is still this transaction's exact installed inode/buffer/mode, with no foreign change. A new directory can be removed only if it is this transaction's recorded directory and is empty after the authorized removals. Preserve the original 727-file/364-directory universe, including all 17 preexisting filesystem-only .DS_Store files. No broad checkout, reset, clean, global restore, chmod, recursive removal or ignore-based cleanup is permitted.

Git keeps a durable private whole native-index backup before changing any shared ref/index. It constructs separate native-successor, commit-only and two semantic-check indices. The selected successor must retain all 58665 untargeted whole raw v2 records exactly, including stat fields, flags/stages, modes, padding and names/OIDs. Only the derived TREE extension may be invalidated, rebuilt or dropped; full before/after raw-map-to-Git-tree semantic equality is required on separate checking copies. No other extension is accepted. The current0644 native mode is retained. Commit and native staging universes are compared independently, so existing foreign staging cannot enter the commit or be lost.

A private tree/object may exist before shared mutation. The new commit has exactly the old ff36 parent and the22-path20A2M delta. The native index lock is acquired exclusively, written/fsynced, and retained if the operation stops before replacement. The old master ref is changed by compare-and-swap; only this held index lock is then atomically renamed over the current native index and fsynced. If interrupted between these phases, do not blindly restore the whole index or roll the ref back. First authenticate old/current ref and raw index, successor, lock ownership and journal; any separately authorized recovery must preserve all foreign staging records. This preparation supplies no automatic ref/index recovery function.

Remote parent verification, immutable commit:refs/heads/master push without force and final remote verification each recheck the exact effective singleton fetch/push route and authorization-bound routing snapshot immediately before the remote command. Failed/ambiguous push is not success. Retain literal command receipts; an exact later read-only remote check may be separately authorized by root. Do not repeat publication, force-push or delete the local transaction merely because the command failed.

Old completed release_four locks and SUCCESS receipts remain untouched forever by this mechanism. New effort locks and all journal/backup/index files remain locally retained in explicit .gitignore paths. Root alone may authorize any later action after inspecting the concrete retained state. No recovery action is authorized by this document.
