# Portable resumable K2P four-port sweep

This directory contains the corrected graph-derived K2P compiler, the complete
four-port descriptor/rank inputs, the exact hand certificate for the four
previously hard direct relations, and a fail-closed resumable driver.

## Environment

Python 3.11 or newer with the versions in `requirements.txt`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python verify_package.py
```

`verify_package.py` checks every immutable SHA-256 binding, imports the pickled
objects under the shipped compiler, verifies source counts
`536,747,276,276,64,32`, and runs an interruption/resume smoke test on the four
direct hard cases.

## Full sweep

Sequential, lowest memory:

```bash
bash run_all_sources.sh "$PWD/run"
```

This processes source indices 0 through 5 and then writes
`run/FOUR_PORT_SWEEP_MERGED_STATUS.json`.

Parallel, one process per source (use only if memory permits six simultaneous
copies of the approximately 110 MB descriptor/rank input):

```bash
mkdir -p run/logs
for i in 0 1 2 3 4 5; do
  python resumable_four_port_driver.py \
    --package-root "$PWD" --source-index "$i" --output-root "$PWD/run" \
    >"run/logs/source_${i}.log" 2>&1 &
done
wait
python merge_manifests.py --run-root "$PWD/run"
```

## Resume and integrity

Reissue exactly the same command. Each completed canonical class is validated
and reused. Records are committed by fsync plus atomic rename. A separate
advisory lock prevents two writers from processing the same source directory.
The residual manifest is regenerated after every newly computed class by
default.

The immutable bindings are in `INPUT_LOCK.json`:

```text
compiler      9d28d616dd633bde96d49d753df49989e93ff77e5fd05a95952e69a8b2cfedaf
canonicalizer 00a6c18b93bf6cf8368ffee3ffa124363b6ba244d8433bffd11a00cefda00071
```

A record generated by an older canonicalizer, altered input pickle, changed
schema, or corrupted self-hash is rejected rather than reused.

## Output interpretation

Per-class statuses are:

- `separated`: exact quadratic or the exact F2/F3/F4 direct certificate;
- `isomorphic`: exact labelled mixed-graph isomorphism;
- `triangle`: exact ordinary-triangle quotient;
- `restoration_parent`: at least one omitted physical role; direct child
  requests are emitted for restoration;
- `unresolved`: direct no-dummy relation requiring further algebra.

The sweep does **not** infer a larger containment from a smaller marginal.
Every `restoration_parent` record carries the actual target dummy attachment
and all source insertion-edge candidates required to generate direct child
marginals later.
