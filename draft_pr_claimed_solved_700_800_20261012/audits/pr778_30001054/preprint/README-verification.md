## Offline reproduction

Use Python 3.12 or later, standard library only. Unzip the archive into an empty directory. Run inside that directory:

    python3 -B verify_bundle.py --pdf /absolute/path/to/paper.pdf
    python3 -B -O verify_bundle.py --pdf /absolute/path/to/paper.pdf

Omitting --pdf checks the source archive but does not authenticate a separately supplied PDF. --integrity-only checks closed bytes, bindings, scope and provenance without mathematical subprocess replays. The verifier compares every recursive source file to MANIFEST.json and pins the original and four review manifests. The external release ZIP hash is the trust anchor; a self-rewritten manifest is not independent authentication.

Full replay covers the frozen original witness, 44 CLI and 24 integrity controls, independent exact enumerations (1296 first halves, 48 rooted primitive words:16 switch-once and32 without mixed events), positive separated-start controls, relative input equality, geometric controls, priority event comparisons, and guarded custody. Each recipe runs normally and under optimization; some frozen recipes also internally exercise both modes. Exact integer/rational results require exact outputs; no floating tolerance is used. The 48 count is rooted indexed words, not isomorphism classes.

Fourteen new corrupt source-inventory cases must fail in each invocation. These parser controls operate on RAM byte mappings. The independent packets separately test physical missing/extra files, symlinks, a special FIFO and empty directories. Declared tiny temporary test fixtures are created and removed; authored input bytes and inventory are checked unchanged afterward. Use -B to avoid bytecode files, which exact custody would reject.

Root's earlier four-runtime original-package replay and source-body readings are dated receipts, rather than claims that every runtime or source PDF is fetched by this offline command.

## Rebuilding the deposit files

From the extracted closed source, supply the exact separately published PDF and an output directory outside the source tree:

    python3 -B build_package.py --pdf /absolute/path/to/paper.pdf --output-dir /absolute/path/to/rebuilt

The builder validates all source and review closures before writing. It rejects output destinations inside the closed input, symlink ancestors, nonregular outputs and aliases/hardlinks of protected inputs. Writes replace fresh files rather than truncate existing input inodes. It produces the two deposit files, their exact metadata, a convenience upload kit and an inventory. It never contacts Zenodo or uploads anything.

Source and kit ZIP members are sorted, use fixed timestamps, regular0644 modes and DEFLATE level9 explicitly for each member. Byte-identical recompression additionally requires compatible Python/zlib versions; member contents and identities are independently checkable. Recompiling LaTeX is separate from matching the released PDF bytes; PDF timestamps/compiler metadata can change its hash.

Only paper.pdf and source-and-verification.zip are intended for the deposit. The outer zenodo-upload-kit.zip is a convenience kit; its enclosed manifest uses the exact same metadata and those two files. Production publication is performed separately only after the required fresh review loop.
