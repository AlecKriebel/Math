## Independent universal certificate and finite controls

Let (a_0,b_0)=(1,0), and set (a_(n+1),b_(n+1))=(3a_n-4b_n,4a_n+3b_n). Multiplication in the Gaussian integers gives A^n=5^(-n)[[a_n,-b_n],[b_n,a_n]]. For every n>=1, (a_n,b_n)=(3,4) modulo 5: the base case holds, and the update of (3,4) is (9-16,12+12)=(3,4) modulo 5. Therefore b_n is nonzero, so A^n is not the identity. If a negative power were the identity, its inverse positive power would be the identity. This is an all-integer-exponents proof, independent of finite testing and of the author's trace-recurrence implementation.

Direct rational multiplication gives A^T A=I and det(A)=1. Every integer power preserves Euclidean lengths, so none strictly contracts all nonzero vectors. Orthogonality alone is insufficient for infinite order: I, -I and the quarter-turn are explicit finite-order controls. For the separated-end mechanism, if a connected compact n-ended core is displaced into one tail U_j, all n-1 other global ends lie in one component of its complement. A homeomorphic image of the stipulated original core must have exactly one global end in each complementary component. The count contradicts this when n>=3. It does not contradict it when n=1 or n=2. The actual existence of the core and the analytic proper-discontinuity step remain separate mathematical obligations; this counting check does not model the complete surface or prove their hypotheses. ## Independent hostile cases and observed trust boundaries

HOSTILE_CASES.py adds **64 rejection controls per mode**, reproduced byte-for-byte under ordinary, -O, and -OO execution. It covers changed/missing/extra files, extra empty directories, FIFO special files, linked manifests/members/directories/roots, ancestor and lexical aliases, copied-code substitution, duplicate JSON keys/members, Boolean/float/negative/NaN sizes, Boolean/float problem IDs, unknown schema fields, malformed containers/digests, traversal/absolute/double-slash/dot/backslash/NUL paths, co-rebinding, and duplicate/nonfinite/wrong-type stdout. The copied-checker pre-execution authentication is explicitly faulted and rejects before running altered code. These are deterministic probes of inspected code, not a claim to enumerate every hostile input.

Three boundary observations are retained in the receipt, with their conditions:

1. **Ancestor symlink alias:** The historical publication wrapper rejects a direct root symlink and linked descendants but accepts a symlink in a root ancestor when the same authenticated packet lies below it. Its `.absolute()` root convention does not promise an ancestor-free canonical path. This did not substitute any file bytes. The new guard rejects every symlink ancestor and lexical alias.
2. **Replacement external anchor:** Rebinding a root README and its outer inventory fails with the fixed original external manifest pin. Supplying the newly computed replacement outer pin makes the historical wrapper accept those newly trusted outer metadata bytes. This is the expected external-anchor boundary; an attacker who controls the trusted anchor has changed what is trusted. The new guard pins all 27 files, including outer metadata, independently of that supplied replacement.
3. **Legacy author wrapper under inherited optimization:** In a safe controlled fixture, CHECKS.py was replaced by an explicit assertion followed by the old receipt, and the author manifest was rebound. A clean ordinary child rejects it. With inherited PYTHONOPTIMIZE=2, the old standalone author VERIFY.py accepts, because both its ordinary and optimized children erase the assertion. This does not bypass the frozen publication wrapper: even a consistently rebound outer inventory is rejected at its frozen inner manifest anchor before execution. Its normal replay environment also clears PYTHON variables. The new guard rejects the altered checker at the all-27 pin check before any child can execute it.

These observations do not call for editing the immutable historical packet or changing its mathematical proof. They require retaining the documented trusted external pins and using the publication bootstrap, or using the new all-27 guard. The old standalone verifier must not be advertised as a general hostile-input loader. A future replacement wrapper could reject ancestor aliases and enforce nonoptimized nested children even without relying on the publication layer.

## Separate hardened guard

HARDENED_VERIFY.py is an independent supplemental artifact; no original verifier was edited. It has these narrower and checkable guarantees:

- A hardcoded digest binds the full actual-Git pinset. All 27 file buffers and the complete five-directory inventory must match before execution.
- Canonical absolute roots are required; root/ancestor symlinks and lexical dot/parent aliases are rejected. Recursive inventories reject descendant symlinks, extra directories and special files before file reads. Each regular file is opened with O_NOFOLLOW, read with its expected size bound, and checked against before/after descriptor metadata and its pinned digest.
- All JSON is parsed after byte authentication with duplicate-key and nonfinite-constant rejection. Stored receipts and stdout types/schema are checked explicitly.
- Execution occurs only from an authenticated isolated copy, with full reauthentication immediately before each program, Python isolation, sanitized PYTHON variables, own-folder temporary directories, and 180-second timeouts for top-level historical children. A subprocess timeout is a failure, not a pass.
- The isolated copy and original packet are reauthenticated after all replay. REPRODUCE.py additionally compares actual immutable Git bytes before and after the full reproduction.

The source root was canonical in both authentication reports. Historical code was inspected for hidden executable input: it imports standard-library modules, runs explicit pinned Python program paths without a shell, uses no network, evaluates no source-material strings, and takes only controlled paths/anchors. Mutation programs do execute deliberately authored safe fixture programs; that behavior is visible and confined to temporary copies. The publication manifest is not treated as sufficient authority to execute a newly substituted checker.

These are local integrity guarantees under a trusted interpreter, standard library, operating system, reviewed bootstrap, independent pin record, and a quiescent filesystem. They are not an OS sandbox, race-proof against a concurrent privileged/local attacker, formal software verification, or protection against replacement of both trusted audit code and its trusted external pin. Directory-ancestor races, resource exhaustion outside the explicit size/time bounds, hostile runtime libraries, and hardware faults are not certified away.
