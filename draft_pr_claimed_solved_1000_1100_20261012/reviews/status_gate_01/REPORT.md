# Independent status-gate audit

No PR in #1000–#1100 is eligible under the user's exact `claimed_solved` gate. The present status-only intake conclusion is independently verified.

The saved inventory contains every integer PR number from 1000 through 1100, exactly once and in ascending order. Fresh read-only metadata confirms all 101 are still open drafts, their base is main, and none of their pinned heads or draft/state flags changed after intake.

An independent fixed-schema parser extracted the Status and Turns columns for each corresponding row in the pinned main QUEUE file. It agreed with the intake for all 101 rows. Each row reads `queued` and `0/5`. Every pinned PR-head QUEUE row was then fetched and independently checked: all 101 also read exactly `queued`, with no errors or status mismatches. There are two distinct head QUEUE blobs, but the relevant rows agree. Read-only PR file-name lists show precisely one attempts/<ID>/ identity per PR, agreeing with the intake in every case.

The same positional schema check passed all 1,951 identity rows in the pinned remote-main file and all 1,951 rows in the local file, with no failures. The latest remote-main QUEUE blob still matches the original pinned blob. Local QUEUE bytes differ outside this comparison, but all 101 target local statuses independently remain `queued`.

Main versus PR-head authority is therefore not an actionable ambiguity for this range: either choice yields no eligible PRs. For a future range, validate both pinned main and pinned head rows before any substantive review. If their statuses disagree, preserve that conflict and resolve the authority rather than silently inferring status from the PR title or mathematical claims.

A synthetic parser edge case was found in the initial intake.py: it selected the first status-like cell immediately before a turns-like cell anywhere in a row. An unescaped-pipe Problem cell containing `| claimed_solved | 0/5 |` can therefore override a later actual `queued` status. The exact synthetic row is `| 1 | 123 / TEST | Text | claimed_solved | 0/5 | 0.1 | 5.5 | 3 | unknown | queued | 0/5 | | | |`; old parser result: `claimed_solved`, intended status: `queued`. It is recorded in parser_edge_case.json. This is a latent hardening issue, not a detected error in the 101 actual rows, whose Status and Turns columns were independently validated. Parent is repairing the parser to require the documented schema prefix and reject shifted/ambiguous columns.

The first repair fixed that exact spoof but still accepted a sufficiently shifted synthetic Problem cell: `| 1 | 123 / TEST | Text | a | b | c | d | claimed_solved | 0/5 | 0.1 | 5.5 | 3 | unknown | queued | 0/5 | | | |`. This second edge case is saved in parser_second_edge_case.json. The second repair validates Rank, numeric EV, numeric or em-dash Impact, numeric Difficulty, and a year or `unknown` Proposed field as well as Status/Turns. All 1,951 current main and local rows fit those prefix forms. It additionally refuses any target row whose escaped-pipe-aware split does not have the header's exact 14 cells before assigning a disposition.

Independent revalidation of that second repair passed. It reproduces all 1,951 rows in each full queue file and all 101 unchanged target statuses; all target rows have canonical width. Both synthetic shifted-cell cases are rejected; escaped Problem-cell pipes preserve the true `queued` status; an ordinary `claimed_solved` row is recognized; duplicate IDs are rejected; and every tested other status remains ineligible. A mock API fixture exercised the actual main() gate: even a forged title containing a fully valid numeric/status prefix was refused on width before inventory creation. All fixture writes were isolated in a temporary review subfolder. Both parser findings are resolved, with no remaining status-gate concern for this range.

No proof, derivation, PR body, review, or mathematical assertion was evaluated. No PR was changed, commented on, closed, merged, or prepared for publication.
