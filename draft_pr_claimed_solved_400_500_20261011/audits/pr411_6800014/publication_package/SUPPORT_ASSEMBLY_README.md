# Research-note asset assembly

The assembly produces exactly these three regular files under assets/: the root's exact six-page PDF, a standalone source ZIP, and a verification/support ZIP. Source material is staged under source_bundle/; supporting material is staged under support/. The final paper under paper/, the original provisional note, and the accepted verification_v2 source remain untouched.

The standard-library builder is SUPPORT_ASSEMBLY_BUILD.py. Run it from any working directory with explicit paths:

    python3 SUPPORT_ASSEMBLY_BUILD.py --case /absolute/path/to/pr411_6800014 --python /absolute/path/to/private-venv/bin/python --private-dir /absolute/path/to/pr411_6800014/private_sources/support_assembly/fresh-run

The private interpreter must already contain SymPy 1.14.0. Pass its venv symlink path verbatim, rather than resolving it to the base interpreter. The private run directory must be new and within the explicitly owned private_sources/support_assembly/ subtree. The builder disables bytecode and user-site resolution and removes PYTHONPATH for each actual mathematical replay. It does not create a runtime, contact external services, or use Git.

Before copying, the builder authenticates the final paper TeX/PDF, the accepted core's real whitelist/seal, and both reviewed root scripts against supplied independent pins. It checks all 71 core payload hashes, the complete 73-file regular inventory, and the actual separate parent SOFTWARE_GATE_ACCEPTANCE_V2.json. It copies the core with no inserted extras. Twenty-five additional complete authored artifacts are copied by an explicit selection list. This surrounding selection is PARTIAL, with retained original references and limitations; it does not pretend to reproduce any full sealed reviewer corpus or private primary-source archive.

SOURCE_MANIFEST.json and SUPPORT_MANIFEST.json positively list all their respective payloads except themselves. Their actual hashes are recorded externally in SUPPORT_ASSEMBLY_RESULTS.json and the final assembly seal. The assembly allowlist excludes itself and the final assembly seal. The final seal carries the actual allowlist hash, input pins, manifest hashes, and asset hashes. No object claims to contain its own hash, and no cycle or fabricated self-hash is introduced. These are unkeyed custody/integrity records, not signatures or semantic proofs.

ZIP serialization uses ZIP_STORED to avoid compression-library variation. Entries have sorted unique safe POSIX names, timestamp 1980-01-01 00:00:00, Unix regular-file type and mode 0644, no extras/comments, and no encryption. Directory entries are omitted. The builder reads every member back and checks exact bytes against the positive member set, rejects unlisted/missing/duplicate members and special modes, and confirms repeated serialization is byte-identical. It writes clean private extractions under a path containing spaces and verifies all extracted bytes.

Seven private malformed-archive tests cover traversal, absolute paths, backslashes, symlink mode, FIFO mode, unlisted members, and duplicates; direct unsafe-name tests cover additional canonicalization cases. These are packaging tests only. No replacement mathematical checker is introduced. The existing accepted core is executed normally and with -O; both existing root scripts are executed in both modes and their parsed outputs compared exactly with the reviewed native JSON results. The core's 73-file inventory is rechecked afterward. Raw stdout/stderr, negative ZIPs, and extracted test fixtures remain private and outside every delivered archive.

The copied PDF is byte-identical to the root's reviewed 90558-byte PDF. The source ZIP has three members: standalone TeX, concise build/status/AI README, and source manifest. The support ZIP has 100 members: intact 73-file core, 25 explicit additional artifacts, the wrapper README, and support manifest. It includes no third-party full sources, raw search envelopes, runtime, venv, caches, or private fixtures. The known family/value and July 2018 announcement are attributed, and no firstness, novelty, current community-open, inaccessible journal-text, or human-peer-review certification is added.
