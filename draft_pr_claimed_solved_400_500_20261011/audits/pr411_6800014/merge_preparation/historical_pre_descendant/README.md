# PR411 administration preparation

This standard-library helper prepares three separately approved phases: **integration**, **ready**, and **ordinary merge**. It contains no mathematical logic and has not performed native writes. No accepted later scientific head/map or genuine published DOI/tracker receipt exists yet in this preparation. Parent inspection and explicit approval of each concrete plan remain required. The current initial gate observes PR411 open/draft/unmerged at `ac8b960bdda61c154cc30d7e3aba70389a9b139e`, header-derived `claimed_solved`, turns 2/5; that head is not hardcoded as the later approved scientific source.

## Preservation and scope

The initial native PR/head/ref/QUEUE gate runs before any local evidence or selected scientific file is opened. Contents QUEUE bytes are Merkle-bound to the exact commit. The gate is repeated after administration evidence checks and immediately before writes. Nonclaimed status, changed turns, head/ref/repository/base drift or unexpected readiness stops the phase.

Integration computes a Git merge commit with ordered parents `[approved_scientific_head, fresh_main_head]`. Its tree equals fresh main with only the complete root-approved `unsolved_math_prioritization/attempts/6800014` subtree and selected QUEUE cell interiors overlaid. The four selected cells are Status=`claimed_solved`, Turns=`2/5`, Findings linking the exact approved `PUBLICATION.md` or `README.md`, and the actual published DOI. Every other queue byte/cell and every unrelated tree entry/mode remains unchanged. Main's `already_solved`, incompatible turns, existing DOI/Findings or conflicting selected subtree is rejected. The source branch's changes from its merge base must be confined to this subtree and these four queue cells.

Immediate nonrecursive Git tree objects are reconstructed with Git's binary Merkle encoding and sort order. Truncated trees, invalid modes/types, duplicate/nested names and blob/hash mismatches are rejected. Unchanged main subtrees remain opaque SHA-bound entries, including their modes; no huge recursive tree listing is trusted. Every accepted selected regular file is checked against complete caller-pinned SHA256, Git blob SHA1, byte size and mode inventory. Unlisted files/empty directories, symlinks, submodules and private/runtime paths in the selected source are rejected.

Use Python 3.14.6 or another compatible standard-library interpreter, `-B`, and existing `gh` authentication. Do not place runtime, credentials, fixtures or journals in delivery. Each `apply` needs that pinned plan, a separately parent/human-approved JSON object with exactly `format=pr411-explicit-administration-approval-v1`, `phase`, `plan_sha256`, `expected_head`, `expected_main`, `authorize_one_phase=true`, and an existing private journal root/run ID. Ready requires draft=true; merge requires draft=false and GitHub clean/mergeable. Ready and merge run as distinct approved phases. Each later phase repeats actual publication/Sheet checks; expired Sheet receipts require fresh authenticated readbacks and a new plan approval.

Integration posts only the administrative queue blob, changed immediate trees and exact two-parent commit, then performs **one nonforce branch PATCH**. Ready performs **one GraphQL ready mutation**. Merge performs **one ordinary merge PUT** with explicit integrated-head `sha` and `merge_method=merge`. No checkout/index/local commit/push, PR-body update, release, force/bypass or outreach path exists.

## Unknown outcomes and API limits

Every mutation has a durable exclusive phase/head claim and fsynced intent before transport; actual safe parsed mutation responses are retained privately. Journal root/run/claim access is descriptor-anchored; symlink ancestors and duplicate claims are rejected. Exclusivity is scoped to the operator's caller-provided journal root: parent custody must pin and reuse that same root. Choosing another root or deleting claims defeats the local no-repeat guard; no global exactly-once guarantee is claimed. Any failed, lost, malformed or mismatching write response stops all write continuation, including Git object POSTs. A separately invoked `reconcile` is GET-only, optionally inspecting the pinned original `--intent-journal` after an uncertain object write. Merge reconciliation permits the expected closed PR state while retaining exact-head Merkle/status gating before local reads. Exact observed presence is an observation; it never grants resume/retry permission or fabricates a prior confirmed response. A stale GET cannot prove an unknown write did not occur. Operators must inspect private receipts; do not delete claims and blindly repeat actions.

GitHub ref PATCH has no expected-old-SHA compare-and-swap parameter. `force=false` protects ancestry, but a concurrently moved ref that is another ancestor of the requested commit can still be updated. GraphQL ready has no head CAS. Ordinary merge's explicit `sha` protects PR head, but does not pin base/main atomically. Immediate native pre/post reads detect observed drift and stop, sometimes **after a visible action has occurred**; they cannot eliminate these races or guarantee absence of unobserved transient moves. GET metadata may also lag. No stronger concurrency guarantee is claimed.

After an ordinary merge, the helper verifies actual two-parent ordering (second parent exact integrated head), actual first-parent ancestry, exact tree overlay against that actual first parent, full scientific positive inventory, unchanged unrelated first-parent paths/modes, queue result and latest-main ancestry/selected registration. Concurrent selected-row/subtree changes reject certification. An unrelated main advance is checked against the actual first parent and can be certified only if that exact overlay verifies; a later main advance must descend from the verified merge and preserve the selected inventory/registration.
