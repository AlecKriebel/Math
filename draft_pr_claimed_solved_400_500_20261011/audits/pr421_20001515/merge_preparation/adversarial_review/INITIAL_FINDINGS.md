# Initial independent administrative findings

The correction decision below applies to the original pinned helper. `FINAL_REVIEW.md` records the independently rechecked corrected frozen pair and supersedes that decision for those final pins.

This review concerns the helper pinned by SHA256 `7825c3b6257e5d100dd1884baee371400edc720f3d3d061038eab6e933b23d3b` and its synthetic driver pinned by SHA256 `103f8dee75d321d5f90af61d8d0a5d8782ffb6e1cd335bdbe8551d4f4f745414`. Original code snapshots are preserved in the private review directory. Line references below refer to that pinned helper.

**Decision:** correction is required before a live plan is promoted. This is an offline administrative review; authentic native receipts, actual package acceptance, live remote state, and live readiness have not been verified.

1. **Status can be taken from a QUEUE blob unbound to the target commit.** `fresh_gate` (line 392) checks the Contents blob hash but does not connect it to the expected commit's QUEUE tree entry. `prospective` performs that connection at lines 607–609, but `selected_at_head` (line 755) never does. In the independent `unbound_contents_status` probe, all Git objects and ref metadata are self-consistent for a withdrawn head; only the Contents response is a stale, correctly hashed claimed-solved blob. `selected_at_head` accepts it and opens five candidate blobs. Move the immutable commit/Merkle QUEUE binding into the common fresh gate before local evidence or case reads, while retaining the early non-claimed skip.

2. **A malformed duplicate selected row is ignored by the early Status gate.** `selected_row` line 187 processes only lines for which `split_cells` returns spans. Appending the same selected-ID table row with Status `withdrawn` and trailing text after its last pipe produces no spans, so the valid claimed-solved row is incorrectly treated as unique. Five candidate blobs are opened before the later unrelated-QUEUE comparison stops planning. Reject selected-ID table lines with invalid spans before any evidence/case read. The supplied duplicate-row test covers only properly parsed duplicates.

3. **Historical merge facts are lost when a response is lost and current scope drifts.** `apply_merge` lines 908–915 attempts full verification after an uncertain PUT. If the PR and historical merge are confirmed but current main has become withdrawn, `verify_final_merge` stops at the current-main scope gate; the exception branch records only `uncertain` and creates no receipt. `reconcile` repeats that failure. The independent `lost_merge_with_current_scope_drift` probe confirms a real synthetic merge, preserves the current-scope no-case-read rule, performs GET-only recovery, and nevertheless leaves no historical receipt. Preserve sanitized historical merge metadata independently of full current-packet verification, labeling both facts accurately.

4. **Readiness is not atomic with the expected head.** The GraphQL body at lines 883–884 contains only the PR node ID. A head advance to a withdrawn commit immediately before POST causes the new head to be marked ready. The subsequent fresh gate stops merge, but it cannot prevent the readiness transition and no final receipt records it. A head field in the mutation response and factual drift receipt strengthen detection; they do not eliminate the race. State the exclusive-branch/no-concurrent-head-writer operational assumption explicitly and do not claim atomic expected-head readiness.

The existing 31 tests pass under normal and optimized Python; the four independent probes reproduce in both modes. AST inspection found zero bare asserts in the helper, driver, or probe.
