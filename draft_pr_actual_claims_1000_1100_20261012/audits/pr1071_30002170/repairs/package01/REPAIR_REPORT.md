## P3-01: prevent every existing output alias before writing

The repair adopts a stronger, clearly stated output policy: **every requested generated file or directory must be absent**, including dangling symlinks; its parent must already be a real directory and have no symlink ancestors; and the output must be outside every descendant of the frozen package. Existing files and directories are rejected regardless of their inode, so existing samefile hardlink aliases cannot be reused. Paths are preflighted before mkdir, output creation, copying, compiler invocation or wrapper subprocess invocation.

`package_paths.fresh_output` implements this static policy. The archive builder preflights its new external file before any manifest read or ZIP write. Checker and PDF scripts preflight a new external directory before mkdir/copy. Because that directory did not exist and starts empty, every possible child output starts without an existing alias: the exact checker copy, both normal/optimized FINITE_CHECKS.json files, stdout/stderr logs and CHECK_RECEIPT; the copied paper.tex, compiler PDF/log, wrapper compile stdout/stderr, and any other ordinary compiler child file. Both subprocesses use the new directory as cwd. The copied mathematical checker retains its exact bytes and the existing explicit normal/-O source/result guards.

The default temporary checker interface creates a disposable parent and a new absent result child beneath the resolved system temporary directory. Reusing an output directory/file is now an explicit error; users must supply a fresh name. The README describes this rule. This is a static local-filesystem preflight for the reviewed source and trusted compiler/program interfaces. It does not promise safety under concurrent filesystem changes or arbitrary malicious executables.

Controls cover direct protected destinations; external symlink/hardlink outputs to paper.tex, paper.pdf, metadata, the manifest and the original proof; new package descendants; linked ancestors; dangling leaves; missing parents; and reused checker/PDF directories containing symlink/hardlink aliases at all intended output filenames. Rejections leave the scratch protected input hashes unchanged. Rejected PDF paths never invoke the disposable compiler. Deleting the absent-output guard deliberately allows an external hardlink archive destination to overwrite scratch metadata, demonstrating the active guard's necessity. No canonical input was used as a destructive target.

## P3-02: consistent regular-file bootstrap and ancestry checks

`package_paths.safe_path` validates names as relative slash-separated member paths without empty/dot/parent components or backslashes. It requires every intermediate component to be an existing real directory and the leaf to be an existing regular nonsymlink file. It also checks containment in the resolved package root. The manifest is checked this way **before JSON parsing**; excluding it from its own payload hash does not exempt it from structure checks.

Ordinary payloads, metadata forms, original preparation/current statuses, copy map, citation, checker source/baseline and authored source qualifications use the same member preflight. The builder reads the manifest and each member through it before output writes. Present external bindings and archives require regular nonsymlink leaves; default clean absent-binding verification still succeeds, and present/required bindings remain strict. Malformed JSON deliberately placed behind a manifest symlink is rejected for the symlink before JSON decoding.
