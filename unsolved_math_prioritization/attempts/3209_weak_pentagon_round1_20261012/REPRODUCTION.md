# Reproduction scope and verification limits

## What readers can verify from this edition

The Clebsch model is defined explicitly, every symbolic lemma and proof is supplied, and the 14-vertex graph, local cut, seven-cycle maximum-cut certificate and three homomorphism vectors are fully displayed. A reader can check their edge differences and reproduce the short contradiction using elementary four-cube distances. No external solver verdict is needed for the negative result. The small graphs and vectors are authored mathematical examples, not a redistributed catalog or certificate collection.

The full independent audits state their algorithms, exact accepted enumeration boundaries, outcomes and adverse controls. Public dataset URLs, lengths, record counts and SHA-256 hashes identify the inputs used. This permits identification of the bounded experiment but is not the same as supplying its software and witness streams.

## What is intentionally absent

Programs, executable patches, raw search collections, imported graph6 files, catalog-derived certificate streams, source PDFs/extractions/renderings and private coordination material are not distributed. No original program command is promised to run from this edition. In particular, the historical shell reproduction workflow compares regenerated certificates with undistributed private references; it cannot run unchanged from this package. The audit replayed certificate checking and did not claim a fresh network download or rerun of every discovery search.

An independently implemented future reproduction would need to obtain the public inputs at the stated identities; verify full bytes, lengths, inventory, order, counts, exact encoding and padding; enumerate the required normalized cuts without omission; construct and verify every prescribed witness; and reject malformed, omitted, duplicated, extra, truncated and empty inputs. Such a workflow is not included or claimed completed here. Catalog-provider generation completeness remains a separate external premise even after exact supplied-record verification.

## Original and hardened checks

The original theoretical Python checker and original computational Python checks rely on assert. Python -O and -OO erase those checks. Deliberately false expectations or a corrupt witness could therefore pass optimized original execution. Normal-mode original checks are valid within their stated input scope; optimized byte-identical output is only output reproduction.

The independent theory checker and hardened replacement retain explicit runtime conditions in normal, -O and -OO. The theory audit records six successful substantive runs and fifteen rejecting controls across those modes. The independent fixed-cut example reconstruction likewise produces identical valid results and rejects a corrupt witness in all three modes; its closed-input checker passed 27 controls. These are independent audit findings, not retroactive repairs to the unchanged original packages.

The original C++ verifier correctly verifies the supplied records but does not alone bind the intended whole input: empty paired files and jointly truncated valid prefixes may pass, and unused graph6 padding can be ignored. The accepted independent audit binds the full genuine input, required order/count and canonical padding, uses active checks even when compiled with -O3 -DNDEBUG, and independently enumerates the local optima containing every global maximum. Its 30 adversarial cases distinguish rejection tests from deliberate demonstrations of the original weaknesses.

## Integrity is not mathematical completeness

The public manifest inventories only the actual distributed files and their exact bytes. It does not claim to contain undistributed audit inputs, software, certificates or source text. Matching this manifest demonstrates edition integrity; it does not rerun the mathematics or remove any external catalog premise. The exact finite results remain bounded, and the full conjecture and all-order global-maximum strengthening remain unresolved by this work.
