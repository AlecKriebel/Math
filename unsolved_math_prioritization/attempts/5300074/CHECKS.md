# Fresh publication verification

The original verify_exact.py and independent_exact_checks.py are copied byte-for-byte. run_checks.py is a new deterministic controller and guarded unittest entrypoint. Its JSON is the complete raw stdout, with no timer or traceback formatting to strip; stderr is required to be empty on accepted runs. It does not rerun the omitted historical audit controller.

Every baseline loads the exact five or four named tests and requires the full count, successful outcomes, zero errors, zero skips, zero expected failures and zero unexpected successes. It verifies the exact enumeration lines: 616 finite cases, 150 distinct degree/angle-set pairs, 238 accepted small invariant subsets and 423 rejected nonrotation sets. Empty, incomplete, skipped and erroneous suites are specifically rejected. Finite forward-invariant sets and finite permuted rotation sets are distinguished in the mathematical report.

The 11 semantic mutations are external-angle substitution, reversed rotation, wrong gap denominator, missing degree-one increment, truncation instead of floor, missing affine interpolation, one too few iterations, wrong centered-parameter sign, wrong other multiplier sign, missing disk cross term and restoring the invalid negative fixture. Each must hit its intended named test; syntax/import failures cannot count. The truncation mutant specifically raises RuntimeError with the exact degree-one fundamental-interval message; only this diagnostic is allowed for this mutant. Baselines cannot have errors.

Tests execute as UID=EUID=1000 on actual 0444 files in 0555 directories. Append opens and new-file creation must fail with EACCES. After these physical probes, a runtime audit hook forbids writes, filesystem changes, sockets and process creation inside tested children. Controllers only create disposable fixture copies. Complete fixture and delivery hashes are compared before and after.

All three optimization modes have separately pinned full stdout/stderr reference bytes and recursively exact JSON types. Delivery controls check every changed member, missing/extra/link/special paths, resealed manifests, exact acceptance and status schema, duplicate/nonfinite JSON, comparator weakening, and hostile Python environment/search paths. Pre-seal receipts describe the earlier seal explicitly. Fresh final receipts are external, not circularly embedded.

These arithmetic and integrity checks do not certify accessibility, Green-function parameter dependence, quasiconformal integration, analytic proofs, literature completeness, or the unresolved neutral-boundary statement. Historical original-report/runner/receipt replay, historical patch application, source-body replay, dataset replay and formal proof-assistant verification are NOT_RUN.
