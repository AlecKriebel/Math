## Principal remaining finding: endpoint semantics are not canonically bound

### Exact passing mutation

Mutation artifact:

`packet_mutations/code_agent/internal_pq_endpoint_swap/certificate_k3p.json`

Starting from the supplied certificate, I changed only the actual rooted and
root-suppressed endpoints/directions as follows:

```text
e_u_p:    u->p   becomes u->q
e_u_q:    u->q   becomes u->p
e_p_r2:   p->r2  becomes q->r2
e_q_r2:   q->r2  becomes p->r2
e_p_r3:   p->r3  becomes q->r3
e_q_r3:   q->r3  becomes p->r3
```

The corresponding endpoint/direction arrays in
`root_suppression.effective_semi_directed_edges` were synchronized. I did
**not** change:

- `rooted_network.reticulations` (which still says, for example,
  `e_p_r2` has parent/choice `p`);
- `display_choice_order` or `choice_index_meaning`;
- any edge ID, vector name, eigenvalue, transition row, construction datum,
  core term, Fourier coordinate, pattern probability, Jacobian descriptor,
  Jacobian matrix, pivot derivative, tangent datum, or sidecar.

Command from the audit directory:

```text
python3 packet_copy/materials/src/verify_k3p.py \
  packet_mutations/code_agent/internal_pq_endpoint_swap/certificate_k3p.json
```

Status: exit 0, ending `ALL K3P CHECKS PASSED`.

Consequently, in the mutated certificate the operative reticulation descriptor
`{"edge_id":"e_p_r2","parent":"p","choice":"p"}` contradicts the
actual arc, whose parent is `q`, while verification succeeds. The paper also
defines `U` on `u->p`, `V` on `u->q`, `A_i` on `p->r_i`, and `B_i` on
`q->r_i` (`combined-paper-clarified.tex:79-95`), whereas this mutation exchanges
those literal endpoint meanings without changing the certificate labels.

### Cause in the implementation

- `src/verify_k3p.py:329-337` constructs `edge_row_by_id`, endpoint, and
  eigenvalue maps from certificate data; there is no canonical expected map
  from each edge ID to its `(parent, child, vector_name)` tuple.
- `src/verify_k3p.py:413-430` requires the stored reticulation descriptor list
  to equal a hard-coded literal list, but it does not relate each descriptor
  row back to the resolved arc.
- `src/verify_k3p.py:478-501` checks that root-suppressed rows mirror the rooted
  rows with the same IDs. Coordinately mutating both copies therefore passes.
- `src/verify_k3p.py:821-824` checks only that the incoming **edge-ID set** for a
  reticulation equals the set of arc IDs whose child is that reticulation. It
  does not check `incoming.parent == arc.parent`, `incoming.vertex == arc.child`,
  or `incoming.choice == arc.parent`.
- `src/verify_k3p.py:1225-1242` now correctly hard-codes the complete Jacobian
  descriptor dictionaries, but those dictionaries terminate at mutable edge
  IDs. Thus they bind `(kind, edge_id, character)` but not the edge ID's
  paper-level endpoints.

### Mathematical impact

The mutation is a global relabelling of the two unobserved internal vertices
`p` and `q`. It preserves the literal leaf distribution, displayed-tree
mixture, rank, and tangent calculation. Therefore it does not give a
counterexample to any theorem and does not show that the supplied numerical
certificate is wrong. It shows that the verifier can accept a certificate
whose advertised edge/parent semantics are internally contradictory.

The manuscript's statement that the verifier “binds the K3P Jacobian and
tangent labels to their executable semantic descriptors” is true at the
descriptor-to-ID layer but too broad if read as canonical endpoint binding.
The coverage inventory's unqualified classifications “exact ordered
reticulation choices,” “rooted arcs,” and “exact ordered 15-column Jacobian
descriptor map” likewise omit this relational qualification.

### Minimal fix

1. In `verify_topology`, require an exact canonical map for all ten rooted arc
   IDs, at least `edge_id -> (parent, child, vector_name)`. This directly binds
   the executable edge IDs to the topology and explicit-witness vector
   placement in the paper.
2. For every reticulation descriptor, resolve `edge_id` and require:
   `arc.parent == incoming.parent`, `arc.child == reticulation.vertex`, and
   `incoming.choice == incoming.parent` (or a separately hard-coded choice
   convention).
3. Add regression mutations for the internal `p/q` endpoint swap and the root
   arc-ID swap below; require failure at the canonical arc map or relational
   reticulation check.

These additions are small, local, and do not require changing any mathematical
certificate value.

## Direct K3P pruning assessment

The new implementation at `src/verify_k3p.py:920-997`:

- obtains each of the four retained edge sets from the rooted graph;
- constructs a topological order and literal parent/child lists;
- derives ordinary transition kernels from edge Fourier eigenvalues;
- runs a four-state postorder likelihood recursion at every internal vertex;
- averages each graph with its independently read inheritance weight;
- separately evaluates the comparison three-star by ordinary-state summation;
- loops over `itertools.product(range(4), repeat=3)`, exactly 64 patterns;
- compares direct network, direct tree, Fourier-network inversion, and
  Fourier-tree inversion exactly.

This is a genuinely different evaluation route from the displayed-monomial
product. It necessarily shares the same input graph, eigenvectors, group
kernel convention, and exact number-field class, so it is a common-input
cross-check rather than an external implementation. That is the appropriate
scope, and the manuscript now describes it accurately.
