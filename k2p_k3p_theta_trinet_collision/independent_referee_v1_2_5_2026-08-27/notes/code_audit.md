### Parser/schema hardening findings

1. **Duplicate JSON names are not rejected.** `json.loads` keeps the final
   occurrence. Two raw hostile K3P certificates passed full verification:

   - `"schema_version":"evil-shadowed-value"` followed by the canonical
     `"schema_version":"3.0"`;
   - a rooted arc with `"parent":"evil-shadowed-parent"` followed by the
     canonical `"parent":"rho"`.

   A first-wins parser and Python's last-wins parser give different raw-certificate
   meanings. This is the only genuine parse-shadowing weakness found. Remedy:
   load every certificate and sidecar through an `object_pairs_hook` that raises
   on repeated names, including nested objects, before any semantic checking.

2. **K2P top-level schemas are open.** Both compact and continuous-time K2P
   verifiers accepted a new top-level `unverified_claim` field. The compact
   verifier also deliberately ignores `schema_version`, as accurately disclosed
   by the coverage inventory. Remedy: require an exact top-level key set and a
   supported schema version, while placing optional prose in an explicit
   metadata object.

3. **Some K3P nested schemas are open.** The K3P verifier correctly rejects an
   unknown top-level field and requires an exact key set for every rooted arc,
   but it accepted an unknown `unverified_claim` nested under
   `parameter_vectors.K`. The coverage document says unlisted descriptive
   fields are informational, so this is not an undisclosed current-field gap;
   it is nevertheless safer to close every operative nested schema.

These are package-hardening issues, not evidence failures for the supplied
unique-key certificates.

   explicit metadata namespace.

   `K_odot_K` row to the nine-row sweep used here. The current verifier already
