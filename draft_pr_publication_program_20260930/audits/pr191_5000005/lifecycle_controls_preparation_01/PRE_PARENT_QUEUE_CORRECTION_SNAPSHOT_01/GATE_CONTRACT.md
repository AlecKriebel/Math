# Proposed PR191 future-gate contract

This folder is proposed code only. It creates no Root gate and grants no publication clearance. Install the eight adapters plus `lifecycle_common.py` only after Root review; invoke operational scripts with Python `-B`. Imports are inert. The proposal folder itself has no `ROOT_PUBLICATION_GATE.json`.

The future case-root `ROOT_PUBLICATION_GATE.json` must have these explicit fields. Root supplies actual final paths and hashes after the successive fresh review loop, including any later repaired version. Bindings are `{path, bytes, sha256}` relative to the PR191 case; file pins use lowercase `sha256`, with `SHA256` also accepted for payloads.

- `schema`: `PR191_LIFECYCLE_GATE_V1`; `status`: `READY_FOR_AUTHORIZED_PUBLICATION`; `PR`:191; `original_head`:`a2791bdd3f7ecd5694aeeeb5dffb21964a5639fe`.
- `qualified_note_route_authorized`:true; `historical_priority_clearance`:false; `all_required_findings_globally_resolved`:true; `last_review_required_repairs`:0. These are actual Root assertions, never inferred from a file's existence.
- `whole_package_reviews`: ordered list of at least two per-review objects with DISTINCT nonempty `reviewer_id`, `authoritative`:true, `disposition` (`PASS` or a globally repaired earlier `REPAIR_REQUIRED`), and nested `report`, `seal`, `root_authentication` bindings. Every nested file is hashed. Latest disposition must be `PASS`, with zero remaining repairs. A report and seal from one reviewer cannot count as two rounds; completed-round counts are the number of reviewer objects.
- `review_input`: binding of the final Root whole-package input record.
- `package_name`: final case-relative package directory. `payloads`: map of every protected package filename to `{bytes,sha256}`. `paper_files`: role map `{pdf:<actual PDF>, source:<actual TeX>, support:<actual verification ZIP>, metadata:<actual deposit JSON>}`. The metadata must upload exactly those three reading/support files, all inside the frozen package.
- `current_proof`: binding of the actual final case proof. `native_proof_paths`: nonempty list of every matching canonical proof copy within the reviewed pending native template, currently `CANDIDATE.md` and `PROOF_V4.md`. A later repaired proof uses its actual name/hash.
- `native_pending_template`: reviewed template directory name under `integration_preparation/`; `native_pending_manifest`: binding of its actual manifest. Its `files` is an exact map of relative names to byte/hash records. The current known count is50; later reviewed manifests are followed exactly, while all16 original files remain in `ORIGINAL_SUBMISSION/`.
- `native_final_template` and `native_complete_template`: fresh names beginning `native_template_final_` and `native_template_complete_`. The latter is used only after actual merge acceptance, to normalize live native merge aliases while retaining the immutable pending/final generation history.
- `native_json_status_paths`: exactly the known factual JSON paths present in the reviewed native manifest: `CURRENT_RESULT.json`, `readiness.json`, `PUBLICATION.json`, `PUBLICATION_PACKAGE_PLAN.json`, `ROOT_SCOPE_RECORD.json`, `review/WHOLE_PACKAGE_REVIEW_STATUS.json`, `review/NEW_MATH_AND_PRIORITY_AUDITS.json`, `review/review_manifest.json`.
- `native_text_status_replacements`: map from `README.md` and `review/REVIEW.md` to one uniquely occurring factual pending-status sentence each. Current exact needles are `PUBLICATION.json contains dated assembly-time publication facts, pending until actual publication and repository acceptance.` and `Those are pending at this dated assembly snapshot.` Rebind if a future reviewer changes either sentence. Proof/code content is never a replacement target.
- `pr_metadata_proposal`: binding of a reviewed JSON object with exactly `title` and `body_before_publication`. Root supplies final credited wording. The preparator appends actual DOI/tracker facts without inventing an identifier.
- `tracker_row_proposal`: binding of reviewed JSON `{original_problem:<column A>, solution_chat_url:<column B or empty>, notes:<column D>}`; column C is the actual assigned DOI URL. Exact target is sheet `1ZljUv5Q98jNXLoHK8WjwrkzSm3dhHC1-7LElcOU7y20`, gid1254632077, tab `Math Puzzles`; exact header is `Original Problem`, `Solution Chat URL`, `DOI`, `Notes`.
- `public_case_paths`: exact Root-vetted relative authored/support paths for final MAIN publication, taken from explicit safe allowlists. `public_case_pins`: map of every still-current immutable scientific/control/support member to `{bytes,sha256}`. Rebind the still-current scientific/control members from the prior339-file checkpoint, including approved support PDF mirrors; the scope always includes all pinned keys. Root case/log/current-template pointer and later factual receipts may change and belong in the explicit path list rather than immutable pin map. No globs. Include only owned sanitized material; do not list full tracker pre-reads, raw external bodies/derivatives/headers, caches, credentials or private Zenodo state. Exact byte/hash-equal PDF/ZIP copies of the approved authored payloads are allowed at explicit support paths; different bodies and render derivatives are rejected. Mandatory packet/proof/native/control/factual references are added by the scope builder itself.

The gate's SHA256 binds actual publication/tracker receipts. Publication receipts also retain exact uploaded file names/sizes/SHA256. `PR_METADATA_REQUEST.json` is prepared locally; Root performs the separate original-head PR metadata/ready transition and saves `PR_METADATA_ACCEPTANCE.json` with `status`:`ACTUAL_ORIGINAL_HEAD_METADATA_AND_READY_STATE_ACCEPTED`, `PR`:191, `original_head`, actual `gate_sha256`, and actual `request_sha256`. The scope builder and merge preparator regenerate expected metadata from the pinned proposal/actual DOI/tracker, then freshly check exact title/body, original head and nondraft state. They create native objects only; expected-old/nonforce MAIN adoption remains a separate authorized Root step. The final self-acceptance receipt is published at the next own checkpoint, not embedded with an invented future commit SHA.
