# v02 local concurrency and failure contract

The independent v01 witness demonstrates a mandatory defect: checking a path and then calling unconditional os.replace loses a receipt created after the check, and can lose an existing view changed after the check. Both raw normal and optimized v01 outcomes show competing content overwritten without an exception. This is rejected behavior. v01 remains sealed and unchanged; its witness sources and raw outcomes are preserved verbatim under preserved_witness_v01.

## Absent receipts and pointers

All receipts and canonical pointers are unconditionally create-only. atomic() rejects a non-None expected preimage for these paths. It stages a bounded regular postimage in the owning generation, flushes it, sets0444, fsyncs it and its directory, and keeps that independent proposed-byte inode as evidence. A separate installation inode is staged with the same bytes. os.link(installation,target,follow_symlinks=False) atomically installs the destination directory entry only if absent. EEXIST never overwrites an existing target, regardless of whether another writer obeys the advisory view lock. A successful installation is directory-fsynced and read back; only the extra installation name is removed afterward. The independent staged proposal remains retained. The no-replace property comes from link(), not a prior existence check.

Existing target bytes, staged incoming bytes and failure records survive a collision. The owning generation receives a create-only LOCAL_WRITE_CONFLICT.json latch; any later binding/sync/pointer in that generation fails. No automatic overwrite, rollback, conflict-latch deletion or failed-artifact cleanup is supplied. The latch is local author/runtime evidence, never an ACTUAL_ROOT_RECEIPT or a completion fact.

## One program-level cooperating-writer protocol

The exact path is draft_pr_publication_program_20260930/ROOT_GLOBAL_FIVE_WRITER.lock, shared by every case, phase and helper-family version. Root must separately install its exact regular0444 payload before actual use; this preparation does not create or touch the real program lock. writer_protocol() returns the exact required source-adoption protocol and payload pin. Future ROOT_LIFECYCLE_SOURCE_ADOPTION_01.json must contain program_view_writer_protocol exactly equal to that dictionary. Merely using a v02-local lock is forbidden.

Root is the sole operator of existing progress/current-case/log views. Every process that may update any of these views, including external Root dispatchers and other case/family helpers, must take nonblocking exclusive flock on this same stable inode before checking or updating them. The carrier must never be unlinked, replaced or rotated. Contention is an explicit bounded failure; the helper does not wait indefinitely. Root must adopt this requirement for all cooperating writers before actual phase use. These are operational prerequisites; the code cannot force another arbitrary process to follow them.

WriterOwnership opens the no-symlink regular0444 carrier, compares descriptor/path device+inode identities, acquires LOCK_EX|LOCK_NB, records the owning PID and inode, and verifies the payload and identities after acquisition, on every ownership check and before releasing. A forked child inheriting the descriptor is not the recorded owner. Any renamed/replaced lock identity fails; phase use records a durable generation conflict before release if the final identity check fails. The descriptor closes and local lease state clears even on error.

Every existing-view write in this source requires current-process ownership AND an active full-five session. Calling atomic() for a single view without that session fails even if the caller holds the lock. sync_images requires ownership; it checks exactly the complete five paths and all old-or-exact-postimage pins and file identities, saves independent preimage evidence, rechecks the entire set, then performs per-file replacements and exact readonly readbacks. No view is replaced before all-five prechecks succeed. The lock remains held through _fresh_accepted, all five checks/replacements/readbacks, native MAIN revalidation, and no-replace LOCAL_GLOBAL_FIVE_SYNC.json installation. pointer() holds it across its full fresh accepted-scope check, successful sync-receipt validation, all-five readonly equality checks, MAIN revalidation and no-replace pointer installation. Release identity is checked before return.

## Failure and recovery

Staged proposed bytes, separate installation bytes if still present, all captured preimages, observed conflicting bytes where readable, and failure records remain under the owned generation. No staged/preimage artifact is silently deleted on failure. A detected content, identity, type or no-replace collision latches the generation and bars future binding/sync/pointer use. The code preserves the competing target at a detected preimage conflict and stops; it does not restore older bytes over it. A detected post-replace conflict retains the actual competing bytes and independent incoming/preimage copies. It does not try an unsafe rollback. A generic I/O failure also retains evidence and returns no success; if no conflict was detected, only exact old-or-postimage retry states may be considered. Root must inspect failures and separately decide recovery; this source offers no latch removal or promotion bypass.

Atomicity remains per file, not across all five files. A later failure can leave some earlier exact postimages installed. There is no successful sync receipt or pointer newly created after a detected conflict. A detected lock-identity conflict during context exit can leave a previously installed receipt from before detection; its generation latch makes subsequent use fail and Root must treat the whole call as failed. Source-only controls do not manufacture an actual receipt to erase that distinction.

## Precise adversary limit

flock is advisory. The existing-view serialization guarantee applies only when every writer follows the same stable-inode protocol and workspace directories remain under Root's controlled namespace. An arbitrary same-UID process can chmod readonly files, write through another descriptor, replace a path or ignore flock. Ordinary portable Python has no filesystem compare-content-and-replace primitive for such an adversary. A check followed by replace cannot close that final window. A platform-specific rename-swap could retain a displaced inode but still would not supply an arbitrary-writer content CAS and would add platform/FFI recovery complexity. v02 therefore uses the enforceable cooperating-writer protocol, preserves detectable conflicts and explicitly makes no blanket same-UID content-CAS guarantee. No-replace installation of a destination name remains unconditional, provided its parent namespace is the intended controlled directory.

A separate non-PASS limitation probe actually reproduces the excluded same-UID final-window mutation under a held lock: a process deliberately ignoring that lock can transiently change a view after the final check, and unconditional replace can erase those unobserved bytes. The source does not detect that case. This is disclosed evidence of the boundary, never a successful race-safety assertion or a reclassification of the fixed receipt collision.

The race suite tests actual child-process contention, both writers reaching the atomic link boundary, canonical pointer collisions, PID/fork ownership, changed captured views, post-replace detectable mutations, retained independent bytes, latches and lock-inode replacement. It does not claim to prevent an undetectable same-UID mutation in the final existing-view replace window. No actual program lock, view, backend, native API, phase, service or Git operation is performed by these tests.
