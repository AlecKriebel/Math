## Required repairs

### F01 — Required Google Sheet service receipt is absent (high)

Helper lines 337–350 accept only an allowed repository tracker path, a commit-bound byte hash and a matching text line. PLAN.md gate 5 describes the same local tracker. This can pass with no Google Workspace CLI invocation, no spreadsheet ID, no sheet/range/row identity and no actual Sheet readback. A local Git row can be useful auxiliary evidence, but it cannot fulfill the user's actual Google Sheet row requirement after Zenodo publication.

Repair: add a distinct, authenticated Google Workspace CLI write/readback service receipt obligation in the plan and helper gate. Bind the exact spreadsheet, sheet/range/row, target ID and DOI, actual command/process identity and exit, request/readback times, and response bytes/hash. Authenticate the service response independently. Require its successful readback after the actual Zenodo publication/readback and preserve the local tracker receipt only as auxiliary evidence. Do not commission this draft using its local tracker gate as a substitute. This report authors no actual service configuration and invokes no service.

### F02 — Independent configuration review is not enforced (high)

Lines 232–233 accept a local commissioning boolean; lines 289–292 bind the adversary gate to the helper SHA and the final gate to antecedent gate bytes. No gate binds the effective configuration. Consequently a campaign note, assessment text/sources, selected tracker path, receipt inventory, or execution parameter set can change after adversarial review without changing the reviewed helper or antecedent gates. The plan requires review of the final helper and configuration, but the configuration part is not enforced.

Repair: define a separate immutable execution-input/parameter manifest, excluding gate pins to avoid a hash cycle. Have the independent adversary and final root gate bind its exact SHA, and have the helper verify that every effective configuration choice and input receipt pin is represented by that manifest. Exact configuration review must occur after the actual package and service receipts exist; this static review cannot provide that future approval.

### F03 — CSV row-span replacement can corrupt an unrelated record (medium)

Lines 142–161 use str.splitlines(keepends=True) for slicing while csv.reader.line_num counts CR/LF physical input lines. str.splitlines also splits vertical tab, form feed, U+001C/U+001D/U+001E, U+0085, U+2028 and U+2029. An unrelated CSV field containing any of those characters makes the helper replace the wrong span, changes the unrelated row and leaves the old target row. Nine additional counterexamples/controls are recorded, including eight concrete CSV examples. This falsifies the general unrelated-byte preservation claim.

Repair: partition physical lines using only CR/LF rules consistent with the CSV reader, or scan record byte spans directly with CSV-aware quoting. After replacement, independently check record identity/count and exact byte spans for every unrelated record. Include these eight controls, CR-only input, CRLF input, quoted target multiline fields, and a target at EOF without a terminal newline. Current pinned ranking.csv has none of the eight extra separator characters; no current native corruption is asserted.

### F04 — Capacity and process bounds are incomplete (medium)

Line 420 budgets only three copies of native baseline bytes, three copies of package file bytes and 1 MiB. The candidate also copies all five gates, publication/tracker/metadata receipts, one HTTP request receipt per package file, historical/effective diagnostics and wrappers. Each input_file may individually be 50 MiB, and receipt counts are not globally bounded. A small package with large otherwise schema-valid receipt JSON can pass the preflight yet exceed free space. The static inspection observed 49,385,228 bytes of native baseline, a 149,204,260-byte minimum preflight, and about 207,056,896 bytes free. A full 50 MiB package would already require over 306 MiB by the helper's own formula and must stop on this filesystem.

Reader.run at lines 196–208 uses unbounded communicate() with no timeout or output cap. The native assess/rank call is in-process at lines 446–467, with no deadline or memory bound. No timeout/failure process receipt is guaranteed when either blocks. These are gaps in bounded execution and diagnostic custody, not evidence that the current flow would hang.

Repair: enumerate and sum every proposed materialized artifact, receipt, temporary native output and retained process stream before creating the candidate; impose aggregate size/count limits and reserve measured headroom. Bound subprocess duration and retained output, terminate/kill and record failures, and run the native assess wrapper in a controlled worker with explicit deadline/resource policy and an actual result receipt. There must be no cache copy/download fallback. A separately commissioned full native reproduction remains necessary.
