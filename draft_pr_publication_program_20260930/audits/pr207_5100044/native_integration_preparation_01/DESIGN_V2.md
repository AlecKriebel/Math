# Verification argument and limits v2

The target claim is conditional: given a separately byte-pinned Root manifest whose event assertions are actually true, the helper either refuses or produces an object-only candidate changing exactly the selected regular blobs while preserving every foreign native tuple and all existing directories. This is an operational claim, not mathematical or publication clearance.

The owned audited core is byteexact 22,049B/SHA256 8a61aee886e7a19bba6c7369944d778614b4099cbe1a060cf7e8acf2f52ec4d5. Its NativeTrees.get authenticates each inspected immediate tree by canonical Git tree order and reconstructed SHA1; opaque equal subtrees stay opaque. lookup, changes, tree_hash and blob_matches are reused. The prior PR206 authority and prior 45% helper are not executed or adopted as current authority.

Construction forms a trie of selected paths, rejects duplicate/ancestor collisions, and requires each old selected tuple to equal its explicit fresh-parent preimage. Rebuilding uses copies of immediate parent maps, updates only selected descendants, and preserves all other tuples. Thus unchanged empty directories and foreign executable/symlink/gitlink modes persist. Candidate verification starts a new tree reader, independently rebuilds expected tree from the frozen parent and sources, checks exact candidate parents/message/tree, compares complete changed leaves and added/deleted directories, then fetches every selected blob and authenticates body byte count, SHA1 and SHA256. The original second parent's stale whole tree is never merged.

Standard verification checks the MAIN lease before and after reads. Explicit after-CAS verification permits current MAIN to differ from the historical parent and reports it; local sync additionally insists actual current MAIN is the accepted candidate. Completion requires GitHub's actual merged/closed/non-draft PR207 plus original HEAD ancestry of the completion parent. GitHub commit endpoint association is a native observation; raw commit object hashing is not claimed.

Every POST receives a fsynced exclusive attempt intent before dispatch. A timeout, nonzero status, malformed response or receipt failure stops the API object and CLI; no retry path exists. Binary blob SHA duplicates are deduplicated. Object creation can leave unreachable GitHub objects when a lease is lost; it cannot move a ref because only object endpoints are allowed. Root's external expected-SHA force=false CAS remains necessary.

Local sync requires an externally pinned actual Root acceptance describing confirmed CAS/readback. It re-verifies actual native bodies before locking. The stable existing writer lock coordinates cooperating writers; its inode/payload is checked throughout. Exact old-or-post local pins allow recovery after interrupted per-file installation. A fresh actual ref readback and exact all-five-file check precede an exclusive actual pointer. Cross-file atomicity and hostile same-UID filesystem protection are deliberately not claimed.

Assumptions and remaining checks: GitHub native endpoint authentication, SHA1 collision resistance for native tree tuples, SHA256 for selected bytes, ordinary unmodified Python/gh runtime, durable fsync semantics, truthful independently reviewed Root event envelope, and cooperating writers. Root must verify prior membership IDs and the semantics of heterogeneous event receipts. The helper checks count/type/list membership invariants and exact file identities, but does not convert source assertions into proof of actual publication or tracker events. Independent adversarial review must challenge those boundaries before any operational invocation.

V2 repairs: QUEUE is mandatory in both phases before any candidate planning. Thus a merge95 overlay cannot pass full verification while silently preserving the fresh queued/0/5 row. completion100 still requires whole-body equality with the accepted claimed_solved/1/5 QUEUE. Every gate-role `{bytes,sha256}` passes strict bytepin before identity equality; Python bool/int equality cannot validate a one-byte receipt. These changes do not change the two-phase dispatcher, source scope, API routes, or actual-authority boundary. Independent new controls reject both known mutants and reject optimized Python before parsing operational arguments. All v1 files are retained unchanged.
