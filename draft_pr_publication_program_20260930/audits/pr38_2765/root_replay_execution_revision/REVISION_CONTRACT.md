## Attempt and failure semantics

Each outer and nested attempted process gets a record before Popen. Available
intended Python source bytes/SHA, exact argv, cwd, supplied stdin, empty separate
stdout/stderr placeholders and the intended-launch ledger precede launching.
The placeholders are labeled prelaunch_empty_placeholder; they never represent
observed empty child streams. A prelaunch retention failure prevents launch.
launch_attempted is true only when the actual process-launch call is attempted.
Actual source absence is recorded explicitly without inventing a source hash.
Administrative readonly Git commands have separate records and no invented
Python child source. The collector and wrapper implementations are retained.

A normal child return records actual_execution:true, completed:true and its
real exit code. CalledProcessError in the nested wrapper retains the real child
exit and full streams before rethrowing the original error. TimeoutExpired
records actual_execution:true, completed:false, exit_code:null, type/message/
traceback and normalized byte partial stdout/stderr, with separate availability
flags for absent streams. OSError records actual_execution:false,
completed:false, exit_code:null and the actual OS exception subtype, errno,
filename, message and traceback. It never fabricates a CompletedProcess or
child exit. Exceptions during prelaunch or retention have a separate stage.
The original child/setup failure is preserved when secondary retention fails.

The wrapper separately records its intended outer helper source/argv/cwd and
helper invocation flags before runpy. It confirms successful prelaunch retention
before invoking the helper. Its setup, generated-file delta capture, nested
ledger, helper-attempt record and CAPTURE_STATUS finalization are protected.
If destination creation fails, the attempt does not overwrite a preexisting
capture destination; the original failure reaches retained outer stderr.

The collector begins its protected attempt with creation of a new owned support
destination and source retention. Root prerequisite preimages are retained
before hash assertions when available. Output creation is exclusive; a raced
foreign output/support destination is never treated as owned. Setup failures
remain FAIL without fabricated before/after closure. Finalization isolates
secondary file/tree/ledger/integrity/publication errors and keeps the original
failure; an unexpected-finalizer guard also records its own failure separately.
Available failure reports can be retried once; programs are never rerun by the
failure-report retry. stderr and an available private failure receipt preserve
original and secondary errors if final publication cannot finish.

A failed support artifact write attempts to preserve available bytes in the
known private attempt, with explicit retention_errors and status FAIL. Nested
capture fallback is allowed only for targets within this audit's private tmp
hierarchy, never in a closed live family. Available fallback records/full bytes
are retained as first-party evidence where possible. Private fallback ledger
paths on a failed attempt are not evidence that the successful support/CURRENT
contract was satisfied. The preserved scratch and failure receipt permit root
to inspect any incomplete or unwritable support retention independently.
