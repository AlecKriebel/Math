## Mechanism: stored configuration loss

After the documented generated-link omission is accounted for, only original `default_preview: paper.pdf` was absent. This is a real configuration loss. Invenio's [draft update component](https://github.com/inveniosoftware/invenio-drafts-resources/blob/cbce42243f7ab2b70edf2347b8e116a89443ea6b/invenio_drafts_resources/services/records/components/base.py#L92) assigns the absent preview as None. The [files schema](https://github.com/inveniosoftware/invenio-rdm-records/blob/fc3cd3fc88175f1845b40176763c551f984e0232/invenio_rdm_records/services/schemas/files.py#L96) suppresses a falsy preview when dumping. During existing-record publication, the [files manager sync](https://github.com/inveniosoftware/invenio-records-resources/blob/3afc25887baf7e2e48067326425e652b8661511b/invenio_records_resources/records/systemfields/files/manager.py#L415) carries the draft preview into public state. Normalizing this loss away would therefore permit an unintended public change.

`PREVIEW_SOURCE_PROBE.json` records **8/8** offline checks executing the actual pinned official preview-update/setter/schema methods against plain local objects. The legacy input clears the preview and the serializer omits it; supplying the original preview restores it while file objects and order remain unchanged. A nonexistent preview filename is rejected. The live deployment's exact revision is not independently known, but its captured before/draft observations agree with this source mechanism.
