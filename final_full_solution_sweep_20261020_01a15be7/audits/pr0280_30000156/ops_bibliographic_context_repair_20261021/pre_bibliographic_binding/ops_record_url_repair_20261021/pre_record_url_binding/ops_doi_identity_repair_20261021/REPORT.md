## Shared identity mechanism

The design follows the root-authenticated primary constraints: ASCII A–Z comparison only in the [2025 DOI Handbook](https://www.doi.org/doi-handbook/DOIHandbook_2025.pdf), body§4.3.4 printed37–38, DOI percent encoding in§4.7 printed40, [DOI resolver help](https://doi.org/help.html), and unreserved percent normalization under [RFC3986§2.3/6.2.2.2](https://www.rfc-editor.org/rfc/rfc3986). The root read those actual primary bodies; this child uses those supplied constraints and does not claim an additional independent Handbook download/read.

The same `target_in_row`/`zenodo_doi_leads` implementation now governs:

1. Whole-sheet target and family lead collection.
2. Current target-before-exemption reconciliation.
3. Independent pre-append current-identity checks and row lookup.
4. Post-boundary readback and final uniqueness checks across all four columns.

It translates ASCII A–Z to a–z explicitly. It does not use general Unicode casefold, NFC/NFKC or compatibility normalization. ASCII digit spelling and full numeric suffix boundaries remain exact:9990,1999,999abc,999-other,999_copy,999.other,999/extra and another registrant are not silently treated as999. Leading-zero **DOI suffixes** remain distinct strings; they are not converted to the canonical target’s integer.

Literal names and unreserved percent-encoded ASCII octets are narrowly normalized. Reserved or nested encoding, standalone Zenodo DOI fragments and recognized record-URL references are **review leads**, not certificates of generic URI equivalence or result identity. A possible target lead stops automatic duplication; it does not authorize skipping scientific identity review. Record URLs with leading-zero IDs are likewise only conservative aliases/leads. The recognizer evaluates every cell and does not rewrite an existing row to make it equal the desired row.

Malformed DOI-like encoding, excessive unresolved encoding depth, and recognized unresolved shortDOI forms/shortdoi.org or short resolver URLs fail closed with a root-review exception. A row containing only such an alias cannot silently produce an empty identity set and allow append. This repair performs no network resolution. The root must obtain read-only evidence and review any such unresolved alias before a later narrowly bound resolution mechanism could be added; there is no blanket alias exemption.

One exact existing desired row remains idempotent with zero append calls. Noncanonical spelling or wording remains a conflicting row requiring reconciliation, even if the narrow DOI name compares equal. Contradictory root exemptions for current identity leads reject before filtering or mutation. Duplicate representations cannot yield a successful uniqueness receipt. If another actor introduces an alias row after the last read, the fresh readback rejects rather than certifying false uniqueness; it cannot undo an external concurrent mutation.
