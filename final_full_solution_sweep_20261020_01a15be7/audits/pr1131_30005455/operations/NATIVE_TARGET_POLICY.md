# Strict PR1131 target policy

This is the review specification for `native_policy.py`, used after the final full-account/GWS gate before each stage upload, stage metadata update and publication POST, and again after successful mutations and during published-ID recovery. It is not scientific or operational clearance. Unknown schema states stop for a new root decision; the code does not weaken the policy automatically to make a write succeed.

Observed reference shapes came from GETs of owned published record23408971, existing unrelated draft21753316, and their native file collections. Private bodies remain excluded; NATIVE_SCHEMA_REFERENCE.json records their exact hashes and keys. No draft was created or edited for schema investigation. These records are different results and do not verify an uncreated PR1131 target.

| Surface | Required semantics |
|---|---|
| Exact legacy identity/state | Positive integer expected ID; matching optional record_id; submitted=false/state=unsubmitted before all stage/publish writes, submitted=true/state=done after publication. A pending metadata edit or unexpected state blocks. |
| Intended DOI/reservation | Exact `10.5281/zenodo.ID` at top level and metadata.doi; exact metadata.prereserve_doi `{doi: intended DOI, recid: ID}`. A supplied DOI override with any different value blocks. Optional legacy doi_url must be exact HTTPS doi.org URI. |
| Extra legacy metadata | Only supplied sealed fields plus generated doi, access_right, imprint_publisher, language, prereserve_doi, relations, custom. Access must be open, publisher Zenodo, optional default language eng, custom empty. Every supplied field still passes the pinned tool's narrow exact verifier. Optional legacy compatibility version relations may only describe the exact initial concept parent using observed zero-based index0; native index1 is checked separately. Unknown extra fields, embargo fields or changed supplied values block. |
| Native publication identity | Exact record ID, is_published/is_draft booleans and draft/published status. Versions must be index1/is_latest=true; new-version workflows are excluded. |
| Native access | Exactly public record/public files, inactive embargo with null reason, status open. No custom_fields. |
| Native DOI infrastructure | Draft pids exactly DOI identifier plus provider=datacite/client=datacite. Published adds exactly the matching OAI identifier/provider. No external DOI provider, alternate DOI or extra PID. This checks an explicit provider-intended reservation before publication; it does not assert that a reserved DOI already resolves. |
| Concept and ownership | Native parent ID equals legacy conceptrecid and differs from record. Parent DOI is exact corresponding datacite DOI. Owner equals authenticated legacy owner, sharing settings remain the observed defaults and communities is empty. Changes to these semantics block. |
| Native metadata | Exact title/date/version, publisher Zenodo, publication-preprint resource ID; exact personal name parts/ORCID/single supplied affiliation, subject list/order, related identifier/relation/scheme/order and bibliography; exact description under only the existing narrow apostrophe exception. Only enumerated metadata keys are allowed. No new copyright, custom or richer alternate metadata. |
| Provider vocabulary decoration | Enumerated id/title shapes, English vocabulary labels fixed to their intended canonical values, optional German labels are nonempty display strings. License ID, English title, description hash, icon, SPDX scheme and canonical license URL are fixed where present. Optional omitted decorations are allowed. No extra semantic keys are stripped or ignored. |
| Native file inventory | Enabled, no manual ordering, exact count/total bytes and names shared by legacy list, native inline entries and native file collection. During staging, a checked subset is allowed; every already observed file is bound. Before metadata update/publish all two uploads are mandatory. Unknown/duplicate/extra/missing files block. |
| Native finalized content | Exact MD5 and integer byte size, extension/MIME, local storage class, visible access; collection status completed and transfer type L. Legacy id, inline id and collection file_id must agree as canonical UUIDs; native version_id and bucket_id are UUIDs and remain unchanged thereafter. Same-byte replacement with different IDs blocks. |
| Content routes | Self/content/container routes must identify exactly the intended record and filename; draft routes are allowed only before publication. IIIF routes must match the exact record/filename and enumerated forms. Unrelated or renamed content routes block. |
| Derived media | Only provider-generated hidden zero-byte `.pdf.ptif` image tiles linked to an exact known PDF file_id are permitted, under enumerated fields/statuses. They are not additional visible intended uploads and cannot change original-file completion, checksum or access requirements. |
| Upload destination | Before uploading, the supplied bucket must equal the fresh exact target's official HTTPS UUID bucket; all observed native bucket IDs must agree. Supplied entry/path/size/hash and metadata-update arguments must equal the sealed local manifest. |

`observe` obtains a fresh legacy target, native target and native finalized-file collection after the whole-account/GWS gate, captures them privately, validates the above, and bounds that observation to30 seconds. The guarded client preserves owner/concept/DOI/metadata and already observed file content/version/bucket IDs across its action. After upload it permits only that one intended added file; metadata update permits no file changes. A fresh first-stage allocation cannot have a native target before its ID exists: its supplied metadata and duplicate gate are checked before allocation, and its exact newly allocated native reservation and empty file state are checked immediately afterward, before any upload/update.

The final publish call has no intervening provider reads or unrelated work between that target preflight and the delegated POST. Zenodo provides no atomic cross-endpoint compare-and-publish lock, so a residual edit race remains. Postflight repeats native/legacy checks; the existing pinned tool retains one-POST lost-response recovery. A later mismatch never authorizes a replacement deposit or a second publication POST. The public compatibility projection separately rejects extra semantic metadata, wrong access/DOI/ownership/concept and wrong zero-based version-parent relations; only the enumerated public resource-type/license structure is projected. The separate public metadata/download verification and exact HTTP200 DOI destination checks remain mandatory before ledger append.
