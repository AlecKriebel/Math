# Private evidence restoration

All new completed cases use disjoint direct compressed LZMA segments in private/chunks15_segments and per-case gzip JSON recipes in private/case_archives_phase15. No whole-case original ZIP or overlapping second whole-case container is created. Each file recipe gives complete byte count/SHA256, ordered16KiB content hashes, mode and nsmtime. Each directory and root has mode/nsmtime. Virtual provider captures have exact path→body hash and ordered chunk recipes; they are clearly distinguished from physical filesystem originals. All actor-returned service_original files, runtime/state/source/approval/intention/certificate files remain physical during execution and are losslessly archived only after completion/readback.

Reader: chunk_reader15.py (standard library, own files only). Reader.keys enumerates the complete content set; Reader.get(hash) returns a chunk and checks segment compressed/raw hashes and bounds. A body is the concatenation of its listed chunks, checked against its byte count and SHA256. Every segment has a separately compressed complete offset index; no duplicate content IDs or unindexed segment members are accepted. Exact member lookup requires the recipe's cohort and case names; paths stored in virtual lookup are original inert case paths.

Cold verifier: python3 -I -S -B verify_custody15.py. Before closing the packet this uses a temporary scratch directory inside private, one reconstructed case at a time, preflighting capacity/reserve. After closure use --scratch ABSOLUTE_EXISTING_OWN_OUTSIDE_DIRECTORY to avoid modifying the sealed namespace. It reconstructs every retained physical byte, file/directory/root mode and nsmtime, reads each back, compares the entire namespace, checks every virtual body/path closure and proves every chunk is referenced. It does not promise original inode topology or original HTTP wire encoding. Hardlinked pending/canonical states may restore as separate files with identical bytes/metadata.

No historical predecessor carrier is expanded, reconstructed or retired here. Operations14's aborted first-final process lost its large in-memory virtual provider captures; its surviving physical tree was preserved in14 and its limitation remains exact/pinned. Operations15 neither recreates those missing originals nor claims complete14 historical VFS custody. The new15 baseline reproduces that14 custody defect as a distinct newly executed case; all15 case VFS closures are retained independently.

Keep all private accounts/ledger/provider bodies and custody carriers private. These inert receipts grant no production action authority.
